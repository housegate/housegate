# Signed INSERT ... SELECT Native Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect native clients to the verified snapshot-query lifecycle and produce complete disposable-network activation evidence.

**Architecture:** A proposed asynchronous agent preparation plan obtains/finalizes/signs a reserved input without occupying the sole client reader; a one-shot plugin continuation and serialized cancellation/forwarding gate deliver it to the host. An independent executing-host plugin validates it and installs a distinct local query-only execution plan. Capability-gated adapters connect the shared runtime to sentio-node and the Arbiter, and a multi-process test harness verifies the full protocol.

**Tech Stack:** Go native TCP codecs, ClickHouse CLI/Go drivers, protobuf/gRPC, Bazel, Docker, immutable release manifests.

**Spec:** [Signed INSERT ... SELECT design](../specs/2026-09-16-signed-insert-select-design.md), D3, D8–D10 and A1–A14; [index](2026-09-16-signed-insert-select.md), [contracts](2026-09-16-signed-insert-select-contracts.md), [replay](2026-09-16-signed-insert-select-replay.md), [coordination](2026-09-16-signed-insert-select-coordination.md).

## Global Constraints

- All [index constraints](2026-09-16-signed-insert-select.md#global-constraints) apply. This plan produces code and acceptance evidence; production activation is outside its authorization boundary.
- Query-only input creates no `DeferredInsertPlan`, sends no sample block, waits for no row terminator and forwards no SQL/Data to ordinary ClickHouse execution.
- Exactly one query is in flight and one codec reads each connection. Keep framed-upstream `OnQuerySuccess` semantics; a local ACK2 is not an upstream success or safe publication.
- Agent preparation returns from `OnQuery` promptly and runs acquisition/finalization off the reader. The relay owns query generation, cancellation, continuation and the final forwarding gate; preparation workers never access the socket or mutate live query/session state. A canceled generation cannot forward, even if acquisition or native FFI returns late.
- Run final analysis/materialization under the reserved profile, sign the final logical SQL, and independently validate it at the executing host even on trusted peer sessions.
- Admit `SQL_x_read_mode` only when absent or `safe`; refuse user settings/session dependencies/parameters and all client row payloads.
- Keep all capabilities disabled by default. Mixed versions refuse; rollback retains accepted v3 history, executable profiles and snapshot artifacts.

### Task D1: Obtain, finalize and sign the agent's query-only input

**Files:** HG agent row, including the relay preparation state machine and plugin-chain continuation. Use A5's analyzer, A2's signer, C2's reservation/status API and the existing durable statement sequence counter. D1 owns the shared generation/coordinator primitive first; D2 extends it for host execution.

**Interfaces:** `sisnapshotquery.Options` contains `Signer auth.StatementSignerV3`, `ControlSigner auth.SnapshotQueryControlSigner`, `Analyzer rewriter.SnapshotQueryAnalyzer`, `Reservations SnapshotReservationClient`, `Catalog SnapshotCatalogSource`, `Seq *sistatement.SeqCounter`, `Journal AgentQueryJournal`, `NetworkID string`, `KeeperShardID uint32`. `auth.StatementSignerV3` exposes `Address() string` and `SignStatementV3(auth.JWSStatementPayloadV3) (string, error)`; the control signer exposes `SignSnapshotQueryControl(binding auth.SnapshotQueryControlBinding) (string, error)` and is implemented by the existing relay signer using C2's purpose. Define these small interfaces in `pkg/auth/snapshot_query_control.go`/`statement_v3.go` when their producer tasks land.

`SnapshotReservationClient` mirrors C2 acquire/lookup/release and its authenticated `SnapshotQueryReservationStatus`, including draining and released identities with no grant. `SnapshotCatalogSource.Load(ctx context.Context, pin replay.SnapshotPin) (replay.SafeSnapshotManifest, replay.AuthenticatedSnapshotQuerySchemaV1, error)` verifies the exact selected-S publication/readiness proof and returns the typed authenticated schema object, never a latest name/type-only catalog. The agent strictly revalidates the object/S/projection and builds RP columns with generation/expression metadata before final analysis. `AgentQueryJournal` persists statement ID, original/final SQL, original client-supplied query ID and its presence, logical database, request ID, grant, full signed envelope, preparation generation, cancel intent, durable launch authorization bound to the exact signed envelope and generation, send/status ambiguity and terminal outcome with `Load`, `List`, `Save` methods over a `Record` with those fields. Proposed stages are `Preparing`, `AcquireUnknown`, `Granted`, `Signed`, `ForwardIntent`, `ForwardAuthorized`, `ForwardUnknown`, `Forwarded`, `CancelPending`, `Released`, and `Terminal`. No journal entry may silently replace a signed operation with a fresh pin. Persist request identity before calling acquire, and preserve cancellation/release debt independently of the client context.

Add proposed `plugin.QueryContext.AgentPrepare *AgentPreparePlan` with `AgentPreparePlan{Prepare func(context.Context) (PreparedAgentQuery, error), ReconcileCancel func(context.Context) error, MaxControlBytes uint64}`. `PreparedAgentQuery` carries a detached final Query and the classification result; it contains no socket, mutable session pointer or live `QueryContext`. Only the relay coordinator applies that result. `AgentPrepare` is mutually exclusive with host `QueryOnly`, `DeferredInsert`, `SuppressUpstreamExecution` and `AbortWithSuccess`; contradictory ownership rejects before starting work. Only A5's exact acknowledged `NOT_SNAPSHOT_QUERY` classification returns the unchanged captured query for continuation through existing plugins; a claimed snapshot query can never fall back after an analysis/acquire/signing failure. Until AST classification finishes, buffer only bounded framed client input and keep observing Cancel/EOF; on a snapshot claim drain only the measured empty marker and reject named/nonempty/excess Data. On a proven ordinary classification, return buffered packets to the existing reader-owned path exactly once, preserving v2 streaming behavior and compression. Do not use a SQL regex or classify every analyzer failure as ordinary SQL.

The proposed `PluginChain` continuation captures the next query-plugin index when an `OnQuery` hook installs `AgentPrepare`, then returns promptly without invoking later hooks. Add an opaque single-use continuation to the hook contract with `ResumeQuery(context.Context, *QueryContext) error`; only the relay coordinator may consume it for the same live query generation. A supported `Hooks` implementation must advertise this continuation capability before the feature can start. Resume after preparation in original order with per-plugin route/peer/forward filters re-evaluated as today; never call the chain from its beginning or rerun a side-effecting hook. Ordinary materialize/sistatement skip only a successfully classified snapshot context, and the existing agent query-auth signer signs the final SQL once before forwarding. Continuation execution must not occupy the client reader or hold the cancellation/forward gate across hooks or I/O.

Transport the canonical input as raw-base64url JSON in one new explicitly owned custom setting `SQL_x_snapshot_query_input`; use the existing `SQL_x_statement_token` for the v3 JWS and `SQL_x_auth_token` for final SQL query authentication. Add the new exact setting key to the enumerable owned-setting list; no prefix-wide exemption. Enforce the reserved profile's SQL/descriptor limits before encoding and bound encoded bytes before decoding. Duplicate settings or a v3 token/input mismatch reject. The input root is recomputed from the decoded input; the descriptor is actually transported, not replaced by an inaccessible root.
