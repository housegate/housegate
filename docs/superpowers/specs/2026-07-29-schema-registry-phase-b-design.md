# Schema Registry Phase B Design (network-state distribution, on-chain commitment)

**Status:** Implemented. **Implementation PRs:** [compute-network-contracts #75](https://github.com/sentioxyz/compute-network-contracts/pull/75), [sentio-core #410](https://github.com/sentioxyz/sentio-core/pull/410), [housegate #113](https://github.com/housegate/housegate/pull/113), [sentio-node #166](https://github.com/sentioxyz/sentio-node/pull/166). **Parent:** [schema-registry design](2026-07-28-schema-registry-design.md) — decisions 2/3/4/5 there are frozen and this spec implements them; §2's invariant (network state is the schema's availability layer, never its integrity layer) governs everything below. **Base:** Phase A merged everywhere (housegate #111 `pkg/schemaregistry` loader seam + `ClickHouseLoader`; arbiter-core #6 `snode.CHTableName`; arbiter #12 `table_ids` CLI mode; sentio-node #165 `table_ids` config + startup derivation). Syncer/pipeline facts below cite the 2026-07-29 exploration of sentio-node `syncer/`+`handlers/`, sentio-core `network/state/`+`common/statemirror/`, and compute-network-contracts.

Phase B moves schema distribution from "each role introspects its local ClickHouse" to "declared once on-chain, mirrored through network state, verified by every consumer" — unlocking roles with no local tables (verifier bootstrap) and making the CH introspection a cross-check instead of the source. The consensus anchor is unchanged: consumers still recompute `SchemaRoot` and refuse startup unless it equals the genesis `schema_root`.

## 1. Scope

In: the `setTableSchema` contract surface + `TableSchemaSet` event; the `TableSchemas` statemirror collection through all four pipeline layers; automatic schema declaration on the CREATE TABLE path; the `NetworkStateLoader` implementing the Phase-A `schemaregistry.Loader` seam; the ClickHouse cross-check (parent decision 5, activated now that the source is remote); verifier bootstrap via network state; the bindings re-sync. Out (§9): the P2 DDL barrier / snapshot minting (Phase C), `ALTER` semantics, batch declaration, multi-network namespacing, automated genesis updates.

## 2. Decisions

| # | Decision | Rationale |
|---|---|---|
| 1 | **Schema declaration rides a new commitgate after-success hook and reads columns back from ClickHouse — never from SQL parsing.** housegate's commitgate gains an optional observer interface `AfterStatementSuccess(ctx, ev)` (marker-interface pattern, same opt-in mechanics as `RouteAware`/`PeerTrustAware` — existing observers are untouched). sentio-node's `database_registry` observer implements it for `CreateTable`: after ClickHouse has materialized the table, it runs Phase A's `ClickHouseLoader` on that one table, computes `payloadexec.TableSchemaHash`, and submits `setTableSchema` on-chain. | The three candidate column sources were weighed in exploration: extending `sqlmeta.AccessedTable` crosses rewriter-go/rewriter-proto for one consumer; parsing `ev.OriginalSQL` re-introduces exactly the "approximate ClickHouse's materialization" hazard that `pkg/replay/chexec` exists to forbid; reading `system.columns` after success is byte-identical to what Phase A already trusts and reuses its loader verbatim. `BeforeStatement` cannot work — the observer returns before the DDL reaches ClickHouse, so the table does not exist yet (`database_registry/observer.go:240-269`). Best-effort delivery of the hook is acceptable: a missed declaration is repaired by the idempotent re-declaration path (decision 6). |
| 2 | **`PlainState` stores the collection as a flat `map[string]TableSchemaInfo` keyed by the composite field string `<databaseId>/<tableId>@<version>`, with an identity codec.** Key assembly/parsing is a pure function pair in sentio-core (`TableSchemaKey`/`ParseTableSchemaKey`); ids cannot contain `/` or `@` (enforced at declaration time — the contract only checks non-empty today). | The statemirror framework supports typed composite keys (`StateCodec` is a bijection seam), but all six existing collections are flat-string + identity, and `TypedMirror.GetAll` hard-fails the whole call on any unparsable field. Staying identical to the existing pattern keeps the change surface mechanical (the exploration's 5-step recipe per collection) and pushes parsing to the read side where a bad key degrades one lookup, not every scan. |
| 3 | **housegate exposes the content lookup as a NEW standalone `registry.TableSchemas` interface (`pkg/registry/schemas.go`), NOT a method on the `Registry` union.** `NetworkStateLoader` (new file beside the Phase-A loader) depends on it and implements `schemaregistry.Loader`. | `pkg/registry/metadata.go:6-19` already codifies this repo convention ("intentionally separate … so consumers that only need routing don't depend on metadata they don't read"), and the union has four compile-time-locked implementations — one of which (`RpcNetworkState`) could only ever stub it. A standalone interface means only the two sentio-node implementations and the yaml/inmemory fixtures opt in. |
| 4 | **Verification ladder in `NetworkStateLoader.Load`:** per table, fetch content → recompute `payloadexec.TableSchemaHash(networkID, schema)` and compare to the mirrored `schema_hash` (mismatch = `ErrSchemaHashMismatch`, fail closed); assemble the set → the caller's existing genesis `schema_root` equality check fires unchanged. Where a local ClickHouse exists (snode; verifier with synced tables), the assembly ALSO runs Phase A's `ClickHouseLoader` on the same refs and diffs the two results — any difference is `ErrClickHouseDrift`, fail closed (parent decision 5). A verifier with no local tables skips the cross-check (that is the bootstrap case Phase B exists to serve). | The parent invariant made concrete: network state is trusted for delivery only; the hash chain (per-table hash → set root → genesis) is the integrity path, and the CH diff catches "the table was created wrong" at boot. The CH loader is thereby demoted from source to auditor, not deleted. |
| 5 | **`schemaJson` is the canonical JSON of `{table_id, partition_by, columns: [{name, type}...]}` in ClickHouse DDL column order, and `schema_hash` = `payloadexec.TableSchemaHash(networkID, schema)` computed by the DECLARER.** The contract stores/emits both without verifying (hash verification on-chain would burn gas re-implementing a Go digest); the chain's job is ordering + custody of the commitment. `networkID` is supplied by the declarer (sentio-node's `storage_integrity.snode.network_id`); a declarer using the wrong network id produces a hash no consumer can verify — fail closed at the consumer, which is the correct failure direction. | Verification lives where it is cheap and already implemented (Go consumers); the event log is the permanent audit source either way. This also keeps the contract network-agnostic — one deployment serves whatever network ids declarers use, and consumers only accept schemas whose hashes verify under THEIR network id. |
| 6 | **Declaration is idempotent and version allocation is contract-owned** (supersedes the parent decision 2's caller-supplied `version` parameter): `setTableSchema` takes no version — the contract increments a per-table version cursor and returns/emits the allocated version. Re-declaring identical content is detected by the caller BEFORE submitting (read latest via network state or `getTableSchema`; skip if `schema_hash` matches), and a redundant on-chain re-declaration is harmless (new version, same hash — consumers resolving "latest" see identical content). `deleteTable`/re-`createTable` does NOT reset the cursor and does NOT clear history (write-once `@<version>` keys; replay of old blocks needs old schemas). | Caller-supplied versions would need cross-process coordination for monotonicity (the parent spec's "strictly monotonic" requirement); a contract-side cursor makes monotonicity a storage property. The skip-if-identical check keeps the common path (node restart re-observing an existing table) from minting junk versions. |
| 7 | **Rebuild-from-genesis works for schemas exactly like every other collection:** `TableSchemas` joins `PlainState` `Clone`/`Save`/`Load` (file + postgres stores) and both mirror paths — `ReplaceInner`'s batch diff (the syncer main loop) AND `SyncMirror`'s minute-cadence full push. Wiping the state store and restarting replays all logs from the contract deployment block and reconstructs the collection. | The exploration flagged `ReplaceInner` as the easy-to-miss wiring point (the syncer does NOT go through per-key upserts); listing both paths as required deliverables closes it. The implicit full-replay rebuild is an existing property worth preserving deliberately rather than accidentally. |
| 8 | **Bindings re-sync is a named deliverable:** regenerate `compute-network-contracts/bindings/bindings.go` via `gen_bindings.sh` and copy it verbatim into `sentio-node/bindings/bindings.go` (currently drifted by 31 lines — the copy realigns it). | The sync is manual with no tooling; making it a checklist item prevents the classic "event exists on-chain, parser doesn't exist in the syncer" failure. |
| 9 | **Rollout order is contract → syncer → declarers → consumers, each backward-compatible:** (1) upgrade Databases via the repo's `Upgrade.sol` flow (new mapping appended after `_permissionAccountsByDb`, UUPS-safe); (2) deploy sentio-node with the new handler (unknown events were already skipped, old nodes ignore `TableSchemaSet`); (3) enable declaration (backfill existing SI tables with a one-shot declare pass — the same code path as the hook, driven per table); (4) switch consumers' loader source once the collection is populated. Consumer switch is a config choice (`schema_source: clickhouse | network_state`, default `clickhouse` until flipped) so a half-rolled-out network never breaks startup. | Every step is independently shippable and reversible; the config-gated consumer switch means Phase A behavior remains the escape hatch until the registry is proven populated. |

## 3. Contract (compute-network-contracts)

`IDatabases.sol`: event `TableSchemaSet(string databaseId, string tableId, uint32 version, bytes32 schemaHash, string schemaJson)`; `setTableSchema(string databaseId, address caller, string tableId, bytes32 schemaHash, string schemaJson) external returns (uint32 version)`; view `getTableSchema(string databaseId, string tableId, uint32 version)` + `latestTableSchemaVersion(string databaseId, string tableId)`; errors `SchemaHashEmpty`, `SchemaJsonEmpty`, `TableNotActive` (reused). `Databases.sol`: storage appended after `_permissionAccountsByDb` (slot discipline per the `__deprecated_*` precedent) — `mapping(string => mapping(string => mapping(uint32 => Types.TableSchema))) _tableSchemas` + `mapping(string => mapping(string => uint32)) _tableSchemaVersions`; guard block copied verbatim from `createTable` (`_requireUsable` + indexer-signer + `isDatabaseWriter`); requires the table active. `Types.sol`: `struct TableSchema { bytes32 schemaHash; string schemaJson; }` beside `Table`. Tests: new `test/DatabasesSchema.t.sol` on the `Databases.t.sol` skeleton (`is Test, NetworkEnv`, `vm.expectEmit` for the event, `revertsFor` series: non-signer, non-writer, inactive table, empty hash/json, cursor monotonicity across delete/recreate). Bindings: `IDatabases` is already in `gen_bindings.sh`'s interface list — regenerate only.

## 4. sentio-core

Per the exploration's five-step collection recipe: `MappingTableSchemas OnChainKey = "TableSchemas"`; `TableSchemaInfo{DatabaseId, TableId, Version uint32, SchemaHash, SchemaJson string}` (+ `TableSchemaKey`/`ParseTableSchemaKey` pure functions) in `network/state/types.go`; `PlainState.TableSchemas map[string]TableSchemaInfo` + `Clone` + `State` interface methods (`GetTableSchema`/`GetTableSchemas`/`UpsertTableSchema`); `StateMirrored` codec field + `newCodec[TableSchemaInfo]()` + **both** mirror paths (`ReplaceInner` diff segment — the syncer main loop — and `SyncMirror` full push) + a single-key `UpsertTableSchema` mirroring `syncDatabase`; `store_file.go` and `store_postgres.go` Save/Load (+ `TableSchemaRow` in AutoMigrate). `TableInfo` gains the two pointer fields (`SchemaVersion uint32`, `SchemaHash string`) updated by the same handler that upserts the content — consumers that only browse `Databases` can see "a schema exists" without fetching content.

## 5. sentio-node

**Syncer leg:** copy the regenerated bindings (decision 8); `handlers/database_event.go` gains `ParseTableSchemaSet` in the sequential-try chain and `onTableSchemaSet` (guard: database exists, mirroring `onTableCreated`; upserts content + the `TableInfo` pointers). No `FilterQuery` change (address-filtered, Databases already listed). Full-replay rebuild follows automatically (decision 7).

**Declaration leg:** `database_registry/observer.go`'s `observerContract` gains `setTableSchema`; the observer implements housegate's new `AfterStatementSuccess` for `CreateTable` events: resolve the physical table (`StorageIntegrityUnsafeDatabase` + `snode.CHTableName` — same coordinates Phase A uses), run `schemaregistry.NewClickHouseLoader(chConn).Load` on that single ref, compute `TableSchemaHash` with the SI network id, skip if the latest declared hash already matches (decision 6), else submit on-chain via `env.SubmitAndWaitTx`. Failures log loudly and do not fail the user's DDL (the hook is post-success; the backfill/re-declare pass is the repair path). A small `declare-table-schemas` maintenance command drives the same code path across all SI tables for rollout step 3 and drift repair.

**Read leg:** `standalone/networkstate` — `RedisNetworkState.TableSchema/LatestTableSchema` (`mirror.Get` by composite field; latest via `mirror.Scan` glob `<db>/<table>@*`), `FromStatecore` equivalents, `convert.go` projection `tableSchemaFromCore`. Both implementations satisfy housegate's new `registry.TableSchemas` interface. Consumer switch: `storage_integrity.snode.schema_source: clickhouse | network_state` (default `clickhouse`, decision 9), wired in `standalone.go` to choose which `schemaregistry.Loader` feeds `snode.Config.Tables` + the `SchemaResolver`; `network_state` mode also runs the CH cross-check (decision 4).

## 6. housegate

`pkg/registry/schemas.go`: `TableSchema{DatabaseId, TableId string, Version uint32, SchemaHash, SchemaJson string}` + standalone `TableSchemas` interface (`TableSchema(databaseId, tableId string, version uint32) (TableSchema, bool)`, `LatestTableSchema(databaseId, tableId string) (TableSchema, bool)`) — decision 3. `pkg/schemaregistry/networkstate_loader.go`: `NewNetworkStateLoader(schemas registry.TableSchemas, networkID string)` implementing `Loader` with the decision-4 ladder (content fetch → `schemaJson` decode into `payloadexec.TableSchema` → `TableSchemaHash` verify → error taxonomy `ErrSchemaContentMissing`/`ErrSchemaHashMismatch` as parent §5 defines); an optional `WithClickHouseCrossCheck(conn)` decorator runs the Phase-A loader on the same refs and diffs (`ErrClickHouseDrift`). commitgate: the optional `AfterStatementSuccess` observer extension is driven by a dedicated, query-id-bound `OnQuerySuccess` lifecycle signal. Relay emits it only for an isolated upstream EndOfStream packet, before exposing that terminal packet to the client; Exception, ambiguous/coalesced chunks, and generic completion perform cleanup without dispatching success. Observer execution remains best-effort and panic-isolated. `pkg/network` fixture mirror: `TableSchemaInfo` in `types.go` (tags aligned byte-for-byte with sentio-core), `InMemoryNetworkState` field + methods, `yaml.go` `table_schemas` section, `configs/local.network_state.yaml` sample block.

## 7. Onboarding flow after Phase B

New table: `CREATE TABLE` through housegate → commitgate hook declares the schema on-chain automatically → operator adds the id to `table_ids` + `merge_guard.tables` → `-print-schema-root` (network-state mode) → governance genesis update → rolling restart. The manual runbook shrinks by exactly the step that was most error-prone (hand-transcribing columns); the genesis update remains deliberate (parent decision 6) until Phase C.

## 8. Testing

Contract: `DatabasesSchema.t.sol` per §3. sentio-core: state/store/mirror unit tests for the new collection incl. `ReplaceInner` diff coverage (add/update visible in a fake mirror) and key-function round-trips. sentio-node: handler test with a fabricated `TableSchemaSet` log; observer test with a fake `observerContract` + real CH (declare-on-create, skip-if-identical, id-with-separator rejection); read-leg tests against a fake mirror. housegate: `NetworkStateLoader` table-driven tests (happy, missing content, hash mismatch, drift vs a fake CH loader result) — pure Go; commitgate hook dispatch test. E2E (extends the SI smoke): create a table through housegate → observe the on-chain declaration → wipe consumer state → boot snode in `network_state` mode → derive/verify/anchor → one INSERT to ACK2. Rollout rehearsal: run the backfill command against a CH with pre-existing SI tables and assert declared hashes equal Phase-A derived hashes.

## 9. Non-goals

Phase C (DDL barrier, `schema_snapshot_id` minting, per-statement schema binding — the registry built here is its storage layer); `ALTER TABLE` schema evolution (declaration covers CREATE only; ALTER on SI tables remains rejected upstream); batch/multi-table declaration transactions; automated genesis root updates; contract-side hash verification; multi-network schema namespacing beyond the declarer-supplied-networkID model (decision 5); pruning old schema versions.

The external Phase-B acceptance smoke is intentionally environment-gated. Its
implementation now creates a previously absent table through HouseGate, waits
for declaration and mirroring, invokes the production backfill entrypoint
twice, cold-boots from network state, and drives one INSERT to RC-bound/ACK2.
Operators must still execute that smoke with the devnet services and transient
credentials described in the sentio-node runbook before the rollout flip.
