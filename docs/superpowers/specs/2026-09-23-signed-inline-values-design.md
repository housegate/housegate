# Signed inline `INSERT ... VALUES` (Tier 2 of issue #153) — Design

**Status:** design, approved section by section on 2026-09-22; implementation plan pending.

**Issue:** [housegate #153](https://github.com/housegate/housegate/issues/153) (Tier 2). **Relation to Tier 3:** none; this design touches no arbiter, arbiter-core, or arbiter-proto surface and does not depend on any Wave 1a work.

## 1. Goal

Let an agent-mode housegate sign an inline `INSERT INTO [db.]t [(cols)] VALUES (...), (...)` statement whose rows, possibly containing expressions, arrive inside the SQL text with no row payload on the wire, so that the statement enters the existing signed INSERT lane and is replayed byte for byte like every other signed INSERT. Nothing downstream of the agent changes: the server ingress, the intake journal, the replay executors, and Arbiter see an ordinary signed streaming Native INSERT.

## 2. Measured facts this design rests on

The official `clickhouse-client` changed how it puts an inline `INSERT ... VALUES` on the native TCP wire between 25.8 (protocol revision 54479) and 26.3 (revision 54484). Measured on 2026-09-22 with a raw TCP capture between a real server and a real client of the same version, `--compression 0`, table `t (x Int64)`:

| Client | Mode | Query text as sent | Client Data packets after the Query |
|---|---|---|---|
| 25.8 | `--query` and interactive REPL | `INSERT INTO t VALUES ` (truncated after `VALUES`) | empty marker, one block with the rows, empty terminator |
| 26.3 | `--query` and interactive REPL | the full statement including the rows | one empty marker only |
| 26.7, 26.8 | `--query` | the full statement including the rows | one empty marker only |
| any | `FORMAT Values` with rows on stdin | `INSERT INTO t FORMAT Values` | empty marker, one block with the rows, empty terminator |

The pinned clickhouse-go fork's `Exec` sends the full statement text and one empty Data block, the same shape as a 26.x client. The server's `system.query_log` records `INSERT INTO t VALUES ` for both shapes because it strips inline data when logging, so query logs cannot distinguish them; the wire capture can.

Consequences: the row in issue #153 that says an inline `INSERT ... VALUES` sends no `ClientData` packet describes 26.x clients and Go drivers; a 25.8 client already streams its rows and is on the ordinary `FORMAT Values` path as far as housegate is concerned. Production runs 26.3, so this design targets the 26.x shape only (D1).

Two more measured facts on 26.3 that the evaluation step (D4) relies on: the `VALUES` table function with an explicit structure string coerces literals to the declared types and evaluates expressions (`SELECT * FROM VALUES('d Date, x Int64, s String', ('2026-01-01', 1 + 2, unhex('4142')))` returns typed rows in input order); it refuses non-constant expressions such as `rand()` with `BAD_ARGUMENTS` ("is not a constant expression"), fails overflow (`Cannot convert value '300' from UInt16: it cannot be represented as UInt8`) and `NULL` into a non-nullable column (`Cannot convert NULL to Int64`), and it does evaluate a scalar subquery such as `(SELECT count() FROM system.tables)`, which is why the closure check in D3 refuses `SELECT` before anything reaches ClickHouse. A 26.x client whose stdin is a silent open pipe blocks before sending an inline INSERT's Query (it peeks stdin); this affects only how tests invoke the CLI.

Existing code the design builds on (paths in this repository unless stated):

- `pkg/storageintegrity/sql.go`: `InsertPayloadEncoding` is the single line that keeps inline VALUES out of the signed lane today; `ParseInsertTarget`, `ResolveInsertTarget`, `InlineInsertSettingKeys`, `RejectUserSettings`, `EmptySettingsHash`, `clientParsedInsertFormats` are reused unchanged.
- `pkg/plugins/sistatement`: `OnQuery` (USE staging, shape gate, compression and settings rejection, target and schema resolution, column list, client revision, statement id), `sqlparse.go` (sample columns: declared order when the INSERT has no column list, otherwise the SQL's order, which must name every declared column exactly once), `seq.go` (durable `client_seq`), and the v2 token signed at `OnQueryInputCompleteStrict` over `SQLHash = DigestString(qctx.Query.Body)` and `PayloadHash = DigestBytes(payload)` with `PayloadFormat = clickhouse-native-data-v1`.
- `pkg/plugins/materialize` and `pkg/rewriter/materialize.go`: the agent-side rewrite of volatile functions before the signers run; rewriter-go's engine covers exactly `now`, `current_timestamp`, `localtimestamp`, `localtime`, `utc_timestamp`, `utctimestamp`, `now64`, `today`, `current_date`, `curdate`, `yesterday`, `rand`, `rand32`, `rand64`, `random`, `randCanonical`, `generateUUIDv4`, and walks INSERT VALUES rows; replacements are constant expressions such as `toDateTime(1758000000)` and `fromUnixTimestamp64Milli(...)`, not bare literals.
- `pkg/plugins/storageintegrity/plugin.go`: the ingress nondeterminism guard `isKnownNondeterministicName` and `containsUnmaterializedNondeterminism`, which runs on the signed SQL and on the forwarded SQL when they differ.
- `pkg/proxy/relay.go`: `runDeferredInsert` (the lane that answers the sample block locally, buffers client payload under `MaxPayloadBytes`, runs `OnQueryInputCompleteStrict`, forwards Query plus exactly one marker, swallows the upstream sample block through the sample gate, replays the payload, writes the terminator, fires `OnQueryInputComplete`) and the one-query-in-flight bookkeeping. The relay must never write a second empty Data terminator; ClickHouse drops the connection on an unexpected empty block.
- `pkg/chproto`: `Codec.WriteQuery`, `WriteRawPacket`, `ReadPacket`, `WriteEmptyDataBlock`, `WriteSampleBlock` (a 0-row block whose encoding is byte-identical to ch-go's `proto.Block.EncodeBlock` at the negotiated revision), `WriteException`. Nothing in this repository encodes a Native block with rows; ch-go (`github.com/sentioxyz/ch-go`, pinned in `go.mod`) does.
- `pkg/replay/nativepayload`: the Native `ClientData` decoder that the ingress and the replay executors use; it requires `ClientCodeData`, an empty block name, `Rows != 0`, the exact declared column count, and a wire type equal to the profile's `NativeWireType`.
- `pkg/replay/payloadexec/column_profile.go`: `ResolveColumnProfile`, the single column-type authority (admitted set: `String`, `FixedString(32)`, `Bool`, `Float32/64`, `[U]Int8/16/32/64`, `Date`, `DateTime`, `DateTime(<tz>)`, `DateTime64(P)`, `DateTime64(P, <tz>)`).
- `pkg/config/storage_integrity_config.go`: the `storage_integrity.agent` block and `validateAgent`; `build.go` `buildAgent`: query plugins run in the order `materialize` (when enabled), `sistatement`, the agent `Signer`, metrics.
- Housegate caps protocol negotiation with the upstream at revision 54470; the agent's synthesized Data packets are framed at that negotiated revision.

## 3. Design decisions

**D1 — Scope is the 26.x shape.** The lane accepts a Query whose body is a complete `INSERT INTO [db.]t [(col, ...)] VALUES <rows>` statement, followed on the client leg by exactly one empty Data block (the external-tables marker) and nothing else. The 25.x truncated shape (`INSERT INTO t VALUES ` with streamed rows) is out of scope and keeps today's behavior: `ParseInlineValuesInsert` reports "no inline rows" for it and `sistatement` leaves it on the ordinary path exactly as now. `INSERT ... SELECT`, `WITH`, `INSERT ... VALUES ... SETTINGS`, `FORMAT Values` with inline data after the format name, query parameters, `async_insert`, and multi-statement input are refused or left to the existing paths (section 8).

**D2 — Materialization is mandatory and fail-closed for this lane.** The `materialize` plugin already runs first in the agent chain and already rewrites VALUES rows. With `inline_values.enabled`, `materialize.enabled` is required at startup (config validation fails otherwise), and a materialization error or a non-`Success` code on an inline statement rejects the statement instead of falling open, because the ingress guard would reject any residual volatile function anyway and a clear error at the agent is better than a 403 from the server.

**D3 — A lexical closure gate, not an evaluator.** `sicore.ValuesClosure(rows)` accepts exactly: parenthesized row tuples separated by commas; numeric literals including a leading sign, decimal exponents and `0x` hexadecimal; single-quoted strings with ClickHouse escapes (`\'`, `\\`, `\n`, `\t`, `\xHH`, and `''`); `true` and `false` (case-insensitive); the arithmetic and comparison operators `+ - * / % = != <> < <= > >=`; parentheses; and function calls of the form `identifier(`. It refuses everything else, including the keywords `SELECT`, `FROM`, `WITH`, `IN`, `NULL`, `DEFAULT`, `CAST`, `AS`, `INTERVAL`, `AND`, `OR`, `NOT`; bare identifiers (a word not immediately followed by `(`); `{name:Type}` parameters; `$$` heredocs; `--`, `#` and `/* */` comments; backtick and double-quoted identifiers; `?`, `@`, `::`, `[`, `]`, `;`; and any function name that `sicore.IsKnownNondeterministicName` or `sicore.IsServerStateFunctionName` accepts (case-insensitive). The nondeterministic list moves from `pkg/plugins/storageintegrity/plugin.go` into `pkg/storageintegrity` unchanged, and the ingress guard calls the shared function. The server-state list is new and initially contains `dictGet` and every `dictGet*` variant, `joinGet`, `joinGetOrNull`, `currentUser`, `currentDatabase`, `currentSchemas`, `hostName`, `FQDN`, `version`, `uptime`, `serverUUID`, `getSetting`, `getMacro`, `tcpPort`, `hasColumnInTable`, `sleep`, `sleepEachRow`, `throwIf`. Both are deny-lists: ClickHouse's `VALUES` table function already refuses non-constant expressions, so the lists carry policy (no time, randomness, or server state baked into a signed row), not correctness.

**D4 — Rows are evaluated once by the tenant's own ClickHouse before signing.** `sistatement` asks a `valuesEvaluator` for typed columns; the production implementation opens a dedicated upstream connection through the same server-mode proxy the session uses (same upstream selection and dialer as the session, `ClientHello` carrying the session's user and database, compression disabled), and sends one ordinary agent query `SELECT <c1>, <c2>, ... FROM VALUES('<c1 T1, c2 T2, ...>', <rows text verbatim>)` signed with the agent's `auth.Signer` in `SQL_x_auth_token` like any other agent query, with the settings `max_execution_time = inline_values.evaluation_timeout`, `max_result_rows = inline_values.max_rows`, `max_result_bytes = storage_integrity.agent.max_payload_bytes`, and `max_block_size = inline_values.max_rows`. The structure string lists the columns the rewritten INSERT will name, in that order, with the declared types spelled exactly as the network-state schema declares them. The evaluator reads Data packets until `EndOfStream`, decodes every block with `nativepayload`, requires each column's wire type to equal the profile's `NativeWireType`, and keeps the blocks in order. Any exception, timeout, transport error, empty result, or type mismatch is a rejection; there is no retry. Connections are pooled per `(upstream address, user, database)` inside the agent process and are ordinary agent queries from the account's point of view; they touch no table and are not reported by `indexing_usage`.

**D5 — The column-type authority is unchanged.** The declared schema from network state drives the structure string, the decoder check, and the encoder; `ResolveColumnProfile` remains the only mapping from a declared type to its wire type, Go value type, and `lthash` kind. The new encoder in `pkg/replay/nativepayload` (`EncodeBlock`) is the decoder's inverse over the admitted set, implemented with ch-go's `proto.Block` and `Col*` types, and is pinned by a round-trip test and by byte identity against captured CLI blocks for literal rows.

**D6 — The signed SQL is the rewritten statement.** After evaluation, `qctx.Query.Body` becomes `INSERT INTO <db>.<table> (<columns>) FORMAT Native` where the column list is the user's list when given (it must name every declared column exactly once, as today) or the full declared list in declared order otherwise, and `<db>` is the resolved target database. `sql_hash` binds this text; the user's original text is not signed and is logged at debug level with the statement id only. Both signers already re-sign at `OnQueryInputCompleteStrict`, so the rewrite is covered by the statement token and the auth token.

**D7 — The signed payload is exactly the bytes the relay writes upstream.** The plan installed by `sistatement` carries typed columns, not bytes, because the Data packet header (BlockInfo fields at revision 51903+, the per-column custom-serialization flag at 54454+) depends on the upstream codec's negotiated revision. The relay lane encodes one client Data packet per evaluated block with the upstream codec (`Codec.WriteDataBlock` produces the bytes; the lane stores them in the plan) before it fires `OnQueryInputCompleteStrict`; `sistatement`'s strict hook takes the payload from the plan when `qctx.SynthesizedInsert` is set instead of from its client-data buffer. The ingress therefore captures byte for byte what was hashed, as it does for a client-streamed payload, and the replay decoders see a block that satisfies every requirement listed in section 2.

**D8 — `runSynthesizedInsert` mirrors `runDeferredInsert` in the reverse direction.** `QueryContext.SynthesizedInsert *SynthesizedInsertPlan` is mutually exclusive with `DeferredInsert`, `SuppressUpstreamExecution`, `AgentPrepare`, `QueryOnly`, and `AbortWithSuccess`. The lane: (1) reads the client's marker with the same liveness arbitration the deferred lane uses; a non-empty block is an external temporary table and is refused as today; `Cancel` before anything is sent answers a local `EndOfStream`, drops the plan and keeps the session; (2) encodes the payload packets (D7) and rejects the query if their total exceeds `max_payload_bytes`; (3) runs `OnQueryInputCompleteStrict`, mapping a `KeepSession` error to a query-terminal rejection and anything else to a closing rejection, exactly as the deferred lane does; (4) `beginActiveQuery`, `up.WriteQuery` with the rewritten body and both tokens, then forwards the client's marker exactly once; (5) waits on the existing sample gate: `TableColumns` is skipped, the sample block is consumed and never forwarded, and its column names, types and order are compared with the plan's expected sample columns; (6) writes the payload packets with `up.WriteRawPacket` in order, then `up.WriteEmptyDataBlock()` once, then fires `OnQueryInputComplete`; (7) hands over to the ordinary upstream loop, so `Progress`, `ProfileInfo`, `Log`, `EndOfStream` and `Exception` reach the client unchanged and only a genuine framed `EndOfStream` after the terminator fires `OnQuerySuccess` and then `OnQueryComplete`. A second client Query while the lane is active is rejected by the existing one-query-in-flight rule.

**D9 — Error dispositions.** Before anything is forwarded (`OnQuery`): every rejection is an `Exception` to the client through the existing plugin-error path, nothing is signed, and no `client_seq` is consumed because the closure gate and the evaluation run before the statement id is minted; the message starts with `storage_integrity inline VALUES:` and names the refused token or function, the parse problem, the evaluation failure (with the server's own message), the type mismatch, or the row or byte limit. In the lane before the upstream Query is sent: a non-empty client block closes the connection after an `Exception`; `Cancel` keeps the session; a byte-limit overflow is a query-terminal rejection; a strict-hook failure follows the deferred lane's rule. After the upstream Query is sent: an upstream `Exception` at the sample step is forwarded and the reserved `client_seq` is wasted, as today; a sample mismatch (schema drift between network state and the physical table) sends an `Exception` naming the first differing column and closes the session rather than trying to cancel an upstream that is waiting for data; an upstream `Exception` after the payload is forwarded, with code 252 keeping the session as on the deferred path; a client `Cancel` after the Query went upstream is forwarded and the lane drains to the terminal packet without success; an `EndOfStream` before the payload was written fails closed without success; transport errors close. A failed statement retried by the client is a new statement with a new id and a fresh evaluation.

**D10 — Configuration.** `storage_integrity.agent.inline_values` with `enabled` (default `false`), `evaluation_timeout` (`Duration`, default `10s`), and `max_rows` (default `65536`); `max_payload_bytes` bounds the encoded payload. Validation: `inline_values.enabled` requires `storage_integrity.agent.enabled` and `materialize.enabled`; `evaluation_timeout` must be at least `1s`; `max_rows` must be positive. `buildAgent` refuses to start when the evaluator's dialer, upstream selector, or signer is unavailable. No new `SQL_x_*` setting is introduced; `settings_hash` stays `EmptySettingsHash`.

**D11 — Observability.** Three Prometheus counters on the agent: inline statements synthesized, evaluation failures, closure refusals. The original statement text is logged at debug level with the statement id and never at info or above.

**D12 — No server or wire change.** The ingress, the intake, the replay executors, arbiter-core, and Arbiter are untouched; the only server-side edit is the behavior-neutral move of the nondeterministic name list into `pkg/storageintegrity`. The feature is agent-only and default-off, so it needs no coordinated release: upgrade the agent, confirm `materialize.enabled`, then enable `inline_values.enabled`; rollback is disabling the flag.

## 4. Components

- `pkg/storageintegrity`: `ParseInlineValuesInsert(sql string) (InlineValuesInsert, error)` returning the target reference, the optional column list, and the verbatim rows text, and refusing trailing `SETTINGS`, `FORMAT`, `SELECT`, and multi-statement input; `ValuesClosure(rows string) error`; `IsKnownNondeterministicName` (moved) and `IsServerStateFunctionName` (new).
- `pkg/replay/nativepayload`: `EncodeBlock(schema, columns) ([]byte, error)`, the decoder's inverse over the admitted types.
- `pkg/chproto`: `Codec.WriteDataBlock(block)` framing a non-empty client Data packet at the codec's negotiated revision, with the same BlockInfo and custom-serialization handling as `WriteSampleBlock` and the codec's compression setting (the signed lane rejects compression, so the packets are uncompressed in practice).
- `pkg/plugin`: `SynthesizedInsertPlan{Columns, SampleColumns, Rows, Packets [][]byte, PayloadBytes}` on `QueryContext`, with the exclusivity rule in D8.
- `pkg/plugins/sistatement`: the `valuesEvaluator` interface (one method: session identity, declared schema, column list, rows text in; typed blocks out), `upstreamValuesEvaluator` with its connection pool, the inline branch of `OnQuery`, and the strict hook reading the payload from the plan.
- `pkg/proxy/relay.go`: `runSynthesizedInsert`.
- `pkg/config` and `build.go`: the block in D10, the validation, the wiring, and the counters in D11.

## 5. Data flow

Client leg: `Query` (full inline statement) then one empty Data marker; later `Progress`/`EndOfStream` or `Exception` as for any query.

Agent `OnQuery` chain: `materialize` rewrites volatile functions to constant expressions; `sistatement` detects the VALUES shape, parses the statement, applies the existing compression, settings, target, schema, and column-list rules, runs the closure gate, evaluates the rows through the helper connection, installs the plan and rewrites the body; the agent `Signer` mints `SQL_x_auth_token` over the rewritten body.

Relay lane: marker read; packets encoded at the upstream revision; `OnQueryInputCompleteStrict` (statement token over the packets, auth token refreshed); `WriteQuery`; marker forwarded once; upstream `TableColumns` skipped and sample consumed and validated; payload packets written; terminator written once; `OnQueryInputComplete`; ordinary upstream loop; `OnQuerySuccess` on the framed `EndOfStream`, where `sistatement` commits `client_seq` and staged USE state as today.

Server leg (unchanged): the ingress receives a Query with both tokens, one marker, the payload packets and the terminator, the same shape a CLI produces for `FORMAT Values` on stdin; it captures the payload bytes, verifies the statement token, classifies the INSERT, derives touched partitions from the Native payload, and admits it.

## 6. Testing and acceptance

Unit: table-driven accept and refuse cases for `ParseInlineValuesInsert` and `ValuesClosure` covering every accepted literal form and every refused construct in D3, including case variants of every name in both lists; a test pinning the moved list equal to the previous ingress list; `EncodeBlock` round trip for every admitted type including boundary values, and byte identity against captured CLI blocks for literal rows (the one-row String payload measured in issue #153, 33 bytes, is the first golden; the existing measurement test captures it in full); `Codec.WriteDataBlock` at each revision tier with compression on and off, and `nativepayload` decoding what the codec wrote; the evaluator against a fake upstream (helper SQL text and structure-string quoting, the four settings, the auth token, compression off, multi-block concatenation, type-mismatch refusal, exception relay, timeout); the `sistatement` inline branch (rejections leave the seq file untouched, the rewritten body, the installed plan, the strict hook hashing plan bytes, and byte-identical behavior to today with the feature disabled).

Relay: fake client and fake upstream tests for the full packet sequence and hook order; marker present, missing, and non-empty; `Cancel` before and after the upstream Query; sample mismatch closing; sample-step exception forwarding; code 252 keeping the session; premature `EndOfStream`; marker fragmented and coalesced across TCP segments; chunked and non-chunked legs; the one-query-in-flight rejection; a raw-packet test that the 25.x truncated shape is treated exactly as today.

Integration (docker, `//pkg/integration:integration_test`, registered in `ci.yml`'s explicit list): the CI server image is 25.8, whose CLI streams inline VALUES, so the primary client is the pinned clickhouse-go `Exec`, which produces the 26.x shape; the CLI path runs only when the installed `clickhouse` binary reports version 26.3 or later and otherwise skips with a printed reason. Cases: an inline INSERT with literals, expressions, and `now()` through agent and server lands, its statement token verifies, and replay through `payloadexec` yields the same state root as the same rows inserted through `FORMAT Values` on stdin; a closure-refused statement receives the prefixed error; the synthesized payload for literal rows equals the CLI stdin capture byte for byte; the truncated shape is refused as before.

Acceptance is met when every test above is green under Bazel, the feature-disabled suite is unchanged, and the CI baseline rule holds (failing sets diffed against clean `main`).

## 7. Rollout and documentation

Upgrade order is free (agent-only, default-off). Documentation: README and `docs/` gain the configuration block, the four-step flow, the error prefix, and the limits; `CLAUDE.md`'s sentence that inline `VALUES (...)` never sends a `ClientData` packet is replaced by the version-qualified statement in section 2; issue #153 receives a comment with the measured table and Tier 2 marked in progress.

## 8. Non-goals

The 25.x truncated shape; `INSERT ... SELECT` and `WITH` (Tier 3); `NULL` and `Nullable`, arrays, tuples, `UUID`, `Decimal`, `Date32` (outside the column-type authority's admitted set); `INSERT ... VALUES ... SETTINGS`; query parameters; `FORMAT Values` with inline data after the format name; `async_insert`; multi-statement input; deduplication of client retries; carrying the original expression text in the signed record.

## 9. Open items

None blocking. Defaults chosen: `max_rows = 65536`, `evaluation_timeout = 10s`, deny-list policy for function names, helper queries excluded from usage reporting. The server-state name list is expected to grow; additions are policy changes recorded in this document's D3.
