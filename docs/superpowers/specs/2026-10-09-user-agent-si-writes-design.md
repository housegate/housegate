## 1. Goal

A user starts a local HouseGate agent with only `-agent-key` (optionally `-agent-owner`), points `clickhouse-client` at it, and can CREATE and DROP storage-integrity (SI) tables and READ and INSERT into them on a network whose SI indexer runs the dynamic table set, without any per-user configuration on the server side.

Concretely, after this design:

- Any account that is a writer of the target database (contract `isDatabaseWriter`), or an operator acting for such an owner, can sign INSERTs into Active SI tables; a static denylist can exclude a signer or owner.
- The agent discovers everything else it needs (network id, which indexer answers table status, lane support, payload limits) from the network, creates its own state directory, and auto-fetches the native engine for inline `VALUES`.
- Several agents may share one key, a lost state directory recovers by itself, and the `client_seq` gap budget no longer wedges an account permanently.
- SI reads either go to the SI indexer or fail loudly; they never silently read the empty ordinary physical table.

## 2. Non-goals

- ALTER, UPDATE, DELETE, lightweight DELETE, TRUNCATE and any schema evolution on SI tables (D8). DROP + re-CREATE remains the only schema change.
- Rate limits and quotas per account (D8). The per-account lane cap in D13 bounds consensus state; it is not a rate limit.
- Billing semantics for SI writes (D4). Only an extension point is defined (§6.9).
- Binding the owner into the signed statement (D3).
- `INSERT … SELECT` (issue #153 snapshot-query lane) and the 25.x truncated `INSERT … VALUES` shape (G10).
- Arbiter-side retirement or compaction of accumulator state. The accumulator stays append-only (`arbiter:accumulator/accumulator.go`, "an append-only, permanent commitment").
- Windows. No release target exists for it (U9).

## 3. Facts this design rests on

Every statement in this section was checked in code or measured; Appendix B records the evidence item by item.

### 3.1 Statement identity

- The agent mints `statement_id = <signer lowercase>:<client_seq>:<16-byte nonce hex>` and uses it as the ClickHouse query id (`pkg/plugins/sistatement/plugin.go` `statementIDFor`, `qctx.Query.ID = statementID`). The seq comes from `<state_dir>/<signer>.seq`, persisted before use, with no lock: `pkg/plugins/sistatement/seq.go` documents "One process per (state_dir, account)", and no `flock`/`LockFileEx` call exists anywhere in the tree (U9).
- The seq is reserved in `OnQuery`. Both signed lanes (`runDeferredInsert`, relay.go:1417, branch at relay.go:1184; `runSynthesizedInsert`, branch at relay.go:1148) share `forwardSignedInsert` (relay_synthesized.go:31), which runs `OnQueryInputCompleteStrict` first (relay_synthesized.go:35) and only then reads the session's current upstream (relay_synthesized.go:42) and calls `beginActiveQuery(q.ID)` (relay_synthesized.go:49). A query id that the strict hook writes into `qctx.Query.ID` is therefore the id Relay records and forwards; no retagging is needed.
- A ~113-character query id (the laned form, §5.1) is safe: ClickHouse 26.3 and 26.7 accept query ids up to 65,536 bytes on the native protocol (`MAX_HELLO_STRING_SIZE = 64 * 1024` in `TCPHandler.cpp`), 25.8 accepted 1,000,000 bytes, and `system.query_log` / `system.processes` store the id untruncated (U1).
- The flat form is parsed by independent copies, all requiring exactly three `:`-separated segments: `pkg/plugins/storageintegrity/plugin.go:708` `parseFlatStatementID`, `pkg/storageintegrity/intake.go:251` `parseFlatStatementID` (exported as `ParseFlatStatementID`, intake.go:282, used by the agent), and `sentio-node:storageintegrityadapter/adapter.go` `parseStatementID`. A four-segment id is refused by all of them.
- arbiter-proto `StatementID {client_account = 1, client_seq = 2, client_nonce = 3}` (`arbiter-proto:proto/arbiter.proto:33-38`); arbiter-core `StatementID` with JSON tags `client_account`, `client_seq`, `client_nonce`; `Flat()` is the only renderer; `Coord()` → `StatementCoord{Account, ClientSeq}` (`arbiter-core:types.go`).
- The envelope-v2 statement JWS binds `statement_id` as the flat string: the FSM recomputes `wantID.Flat()` and compares every field (`arbiter:fsm/userjws.go` `verifyUserJWSV2`); the ingress does the same through `auth.StatementPayloadV2Mismatch` (`pkg/plugins/storageintegrity/plugin.go` `admissionFromState`).
- `_hg_row_id = BLAKE3(domain ‖ framed(network_id) ‖ framed(table_id) ‖ framed(statement_id) ‖ ordinal_le64)` with the flat statement id as opaque bytes (`pkg/replay/payloadexec/executor.go` `RowID`, profile `housegate-row-id-v1`).
- `StatementsRoot` and every authority/attestation digest hash canonical JSON of arbiter-core types through `replay.CanonicalDigest` (`pkg/replay/hash.go`). A new field tagged `omitempty` leaves every existing preimage byte-identical.

### 3.2 Accumulator, admission and consensus parameters

- `SpentIDs` is keyed by the coordinate's `Account` string as opaque bytes: `hashKey(account)` and `leafPreimage(len u16 ‖ account ‖ hi ‖ n_ranges ‖ ranges)` (`arbiter:accumulator/spentids.go`, `arbiter:accumulator/profile.go`). Per key `spent = [1, hi] \ ranges`, `K = MaxOpenGapRanges = 64`; a jump above `hi+1` adds a range, an edge fill never adds one, a mid-range fill splits (`arbiter:accumulator/state.go`).
- Admission order (`arbiter:fsm/admission.go:20-135`): shape and v2 invariants (`MALFORMED`, lines 23-55) → kind (`KIND_NOT_ADMITTED`, 60) → JWS (`MALFORMED` / `INVALID_SIGNATURE`, 67-69) → schema (`SCHEMA_NOT_ALLOWED`, 80-84) → duplicate (`DUPLICATE_CLIENT_SEQ`, 90) → snapshot-query and table-set fences (`Rejected`, 93-101, which the gateway maps to gRPC `Unavailable`, `arbiter:server/ingress.go:55-60`) → `SpentIDs.Insert` (`GAP_BUDGET_EXCEEDED` or `MALFORMED`, 106-110, state unchanged on error) → assign and bind. Every ack code except `ACCEPTED` and `DUPLICATE_CLIENT_SEQ` leaves the coordinate unspent. `reackDuplicate` (`arbiter:server/ingress.go:46-92`) turns an identical resend into `ACCEPTED`.
- Raft commands are protobuf `RaftCommand`s decoded by `arbiter-core:wire/command.go:285` `Decode`, which first runs `validateCommandBytes` (`arbiter-core:wire/snapshot_query.go:1328-1380`): an unknown field anywhere in the command, at any nesting depth, fails decoding, and `arbiter:fsm/fsm.go` `Apply` returns `Rejected{"decode: …"}` without touching state. A voter that does not know a new field therefore rejects every command carrying it, while a voter that knows it may apply the command. This is the consensus hazard every new command field in this design is ordered around (§5.6, §8.3).
- Consensus parameters change only through an authority-signed `UpdateConsensusParams` (`arbiter:fsm/consensus_updates.go`). `TableRegistry` is the precedent for a feature that is absent (nil, omitted from the canonical form) until set and then fixed; its transition rule (consensus_updates.go:109-116) refuses any change, so a raise-only parameter needs its own rule. A consensus update increments only `ConsensusEpoch` (consensus_updates.go:62-75); it does not bump the table-registry `Version`, which only `registryChangedLocked` does (`arbiter:fsm/apply_table_registry.go:28-32`, `reg.Version++` plus `EventTableRegistryChanged`). The snapshot container version advances only when the state needs it (`arbiter:fsm/snapshot.go`, `snapshotVersion = 17`).
- `NodeRegistration` is persisted in replicated FSM state (`arbiter:fsm/state.go:80`, `Registration arbiter.NodeRegistration`), written by `applyRegisterNode` (`arbiter:fsm/apply.go:43-75`) from the command the leader's `RegisterNode` handler proposes (`arbiter:server/membership.go:16-24`, `wire.RegistrationFromPB(req)`); proposals are accepted only on the leader (`arbiter:server/server.go:200-213`).
- sentio-node learns arbiter parameters only through the table-registry follower (`arbiter-core:dataplane/registry_follower.go`: one `GetTableRegistry`, then `WatchTableRegistry(since_version)`, accepting a snapshot only when `snap.Version > f.snap.Version`). Nothing in sentio-node calls `GetConsensusParams` (U12).
- No admission-rejection metric exists in arbiter or arbiter-core (U13).

### 3.3 Authorization

- The SI ingress authenticates the recovered JWS signer against a static `allowed_addresses` list; an empty list admits any valid signature (`pkg/auth/eth_validator.go:192-193`, `:399-400`); config validation refuses an empty list (`pkg/config/storage_integrity_config.go:296-297`) and so does the production chart (`production:charts/sentio-node/templates/node.yaml:18-19`, `:65-66`). The ingress never consults `registry.Access` or the payer.
- The ordinary chain already requires the Write bit for INSERT on an auth-enabled host: `buildServer` prepends `network.NewPermissionCommitGateObserver(reg)` (build.go:472), whose `permissionPolicy` maps INSERT, CREATE TABLE, DROP TABLE and the other writes to `DbAuthWrite`, resolves the principal as the owner after `IsOperator(owner, signer)`, promotes Owner ⇒ Admin|Write|Read and Write ⇒ Read, and unions grants held by `0x000…000` (`pkg/network/permission_commitgate_observer.go`). Commitgate skips maintenance, platform-operator and driver sessions, peer-trusted sessions and origin-side forwarding sessions; the host of a forwarded session runs it (`pkg/plugins/commitgate/plugin.go`). The divergences from the contract are the address(0) union and the missing indexer-signer clause; the SI ingress has no check of its own.
- Contract `isDatabaseWriter(db, account)`: true iff `account == indexerSigner(db.indexerId)` (non-zero) or `perm & 0x08` (Owner) or `perm & 0x02` (Write), reading `_dbPermissions[db][account]` exactly, with no address(0) union (`compute-network-contracts:src/Databases.sol:379-387`). Its NatSpec says Admin (0x04) also grants write; the code does not. `createTable`, `setTableSchema` and `deleteTable` require `isDatabaseWriter(caller)` (`Databases.sol:241`, `:268`, `:288`). `grantPermission` accepts `account = address(0)`.
- Permission encoding: bits `DbAuthRead = 1`, `DbAuthWrite = 2`, `DbAuthAdmin = 4`, `DbAuthOwner = 8` (`sentio-core:network/registry/types.go:17-24`), stored as decimal int64 strings (`sentio-core:network/registry/permissions.go:30-39`; written by `sentio-node:handlers/database_event.go:100`, `:136`). `GetAccountDatabasePermissions(account) map[string]string` is on the `State` interface (`sentio-core:network/state/state.go:41`). The indexer signer is `IndexerInfo.Signer` (`sentio-core:network/state/types.go:9-16`), lowercased on sync (`sentio-node:handlers/indexer_registry_event.go:47`).
- sentio-node `FromStatecore.HasPermission` (`sentio-node:standalone/networkstate/networkstate.go:110-120`) already applies the hierarchy: it calls `MergeAccountPermissions` (OR with address(0) grants) and then `expandAuth` (Owner ⇒ Admin|Write|Read, Write ⇒ Read; Admin alone implies nothing) (`sentio-core:network/registry/permissions.go:20-28`, `:44-58`). Its divergences from the contract are the address(0) union for Write and Owner bits and the indexer-signer clause, which the node models only as a Write row mirrored at database creation (`sentio-node:handlers/database_event.go:72-101`, "signer rotation is only handled at database-creation time") (U11).
- devnet2 has no address(0) grants: the Databases proxy emitted 59 `DatabasePermissionChanged` events since its deployment block 2783225, none for address(0), with `delta` values 1, 5 and 8 only (U4).
- housegate and sentio-node configuration decoding is lenient: `pkg/config/config.go:548-558` uses plain `yaml.Unmarshal` / `json.Unmarshal`, and `sentio-node:config/config.go:359` plain `yaml.Unmarshal`. An old binary silently ignores an unknown key such as `denied_addresses` (U14).

### 3.4 Agent sessions and routing

- Agent mode runs no credential-rewriting hello plugin (`buildAgent`, build.go:1206-1420, registers only `sessionstate` as a HelloPlugin, which does not mutate the hello). The hello forwarded upstream is the client's hello with `ProtocolVersion` capped at 54470. `SessionState.UpstreamHello()` (`pkg/chsession/state.go:198`) returns a clone of exactly that hello, including `User` and `Password`, so it can be replayed verbatim. The per-query agent JWS is not in the hello; the agent signer injects it into each Query (`pkg/plugins/agent/signer.go:84-101`), so a new upstream needs no new signature, but any proxy-generated replay query would be unsigned (U6).
- In agent mode only `sistatement` tracks the session database: it stages a standalone `USE` in OnQuery and commits it in `OnQuerySuccess` only after framed success (`pkg/plugins/sistatement/plugin.go:71-72`, `:148-163`, `:509-523`). Session `SET`s, temporary tables and server-side state are tracked by nothing (U6).
- `Session.RebindToPeer` / `RebindToLocal` (`pkg/chsession/session.go:133`, `:150`) are peer/forward-specific (they write `PeerServerHelloRaw` or clear `IsForwarding` / `RouteTarget`); both go through `handshakeNewUpstream` (session.go:178), which caps the hello, reads the new ServerHello, sets the new leg's revision to `min(hello.ProtocolVersion, srv.Revision)` and resolves the upstream addendum as non-chunked, and `swapAndCloseOld` (session.go:221). `upstreamToClient` notices a replaced codec only when its blocked read fails and `Upstream()` changed (relay.go:1759-1766); Relay refreshes `up` after the OnQuery chain (relay.go:1199). The agent dials through `dialRaw` (build.go:1500-1511), which wraps the conn in `configuredAddressConn` so the inline-values evaluator and post-commit observers reconnect to the session's current endpoint (U6).
- Every indexer's storage RPC and housegate port is publicly reachable on devnet2: `sentio_getIndexerInfos` on `:32003` and `:33003` returns both indexers with `clickhouseProxyPort` 32001/33001 and `storageNodeRpcPort` 32003/33003, and both housegate ports accept TCP (measured 2026-10-08 from a user machine, R2).

### 3.5 Cross-indexer reads of SI tables (G9, measured)

Measured on devnet2 2026-10-08/09 and reproduced locally (U5):

- Indexer-a's own read of `devnet101.swap_new106` is rewritten to `SELECT count() FROM (SELECT * EXCEPT (_hg_row_id) FROM hg_safe.devnet101__swap_new106 UNION ALL SELECT * EXCEPT (_hg_row_id) FROM hg_unsafe.devnet101__swap_new106) AS \`devnet101.swap_new106\`` and returns 3 rows (1 safe + 2 unsafe). The ordinary physical table ``devnet2.`devnet101.swap_new106` `` exists and holds 0 rows.
- Through indexer-b's driver sidecar the same SELECT fails loudly: the driver account has no permission on `devnet101`, so b's rewriter forwards the statement unchanged and b's ClickHouse answers `UNKNOWN_DATABASE`.
- For an account permitted on `devnet101`, b's deployed rewriter (`housegate-rewriter:0.14.0`) emits `SELECT count() FROM remote('localhost:33001', 'devnet2', 'devnet101.swap_new106', '__route__|sentio-node-devnet2-indexer-a:32001|__peer__|…', '<peer JWS>') AS \`devnet101.swap_new106\``: the table argument is the ordinary physical table identifier, a single-quoted string, against the physical database `devnet2`.
- ClickHouse turns that `remote()` into a secondary query (`is_initial_query = 0`) of the form ``SELECT count() AS `count()` FROM `devnet2`.`devnet101.swap_new106` AS `__table1` `` (and ``SELECT `__table1`.`value` AS `value` FROM `devnet2`.`devnet101.swap_new106` AS `__table1` `` for `SELECT *`), reproduced on a local 26.3.37.3 server with `prefer_localhost_replica = 0`. That leg reaches indexer-a's HouseGate as a peer-trusted, non-forwarded session, which bypasses rewrite and the SI chain by design, and reads the empty ordinary table: 0 rows instead of 3. The live secondary query was not observed, because no cross-indexer traffic for an SI table exists in retained logs.

### 3.6 Client behaviour and wire facts

- `clickhouse-client` disables compression by default when the host is `localhost` or resolves to a local address (127.0.0.1, an own interface address) and enables it for non-local hosts; `--compression 0/1` overrides. Verified on the wire (Query packet compression byte) for clients 25.8, 26.3 and 26.7 (`ClickHouse:src/Client/ConnectionParameters.cpp`) (U8).
- Server packets on the deferred SI INSERT lane at revision ≤ 54470 (U7): before forwarding, HouseGate writes its own 0-row sample Data block (`Codec.WriteSampleBlock`, codec.go:723-768, relay.go:1446), LZ4-compressed iff the client's Query enabled compression (codec.go:750). After forwarding, the upstream's TableColumns (11) and sample Data are consumed while the sample gate is armed (relay.go:1844-1858); an Exception is forwarded. Everything after the sample is forwarded raw: Progress (3), ProfileInfo (6), Log (10), ProfileEvents (14), occasionally TimezoneUpdate (17), and the terminal EndOfStream (5) or Exception (2). Data (1), Totals (7) and Extremes (8) follow the Query's compression mode but a normal INSERT does not produce them. Log, ProfileEvents and TableColumns are never compressed below revision 54481 (`revisionMinCompressedLogsProfileEventsColumns`, codec.go:536) and negotiation is capped at 54470 (hello.go:21). Progress, ProfileInfo, EndOfStream, Exception and TimezoneUpdate are never compressed. Today both the agent (`pkg/plugins/sistatement/plugin.go:203-204`) and the ingress (`pkg/plugins/storageintegrity/plugin.go:195-197`) refuse a compressed SI INSERT.
- Release targets are linux/amd64 and darwin/arm64 only (`.github/workflows/release.yml`); Bazel defines linux platforms only (BUILD.bazel:176-192); `pkg/ffifetch` rejects windows. OS-specific code is split by build tag (`pkg/secretsload/anonfile_linux.go` / `anonfile_other.go`) (U9).

## 4. Decisions

### 4.1 Product decisions (binding)

- **D1 — Open writes with a static denylist.** Any address may write SI tables; there is no allowlist to configure. A static `storage_integrity.ingress.denied_addresses` refuses a write when the statement signer or the resolved owner (an `SQL_x_payer` validated by the operator relation) is listed. It applies to the SI ingress lane only and is static configuration (restart to change). The existing `allowed_addresses` stays optional for backward compatibility; empty means open.
- **D2 — Write permission is still required.** The effective principal — the owner when `-agent-owner` / `SQL_x_payer` is validated through the operator relation, else the signer — must satisfy the contract's `isDatabaseWriter` on the target database. **Admin alone is not a writer** (the contract code, not its NatSpec, is what `createTable` / `deleteTable` enforce, so INSERT must agree with CREATE/DROP); **an address(0) grant does not make anyone a writer** (the contract does not union it). Wildcard Read grants keep working for reads. The ordinary write path uses the same predicate (§6.2, R3).
- **D3 — The signer is the accountable writer.** Statement id, arbiter `client_account` and `_hg_row_id` are derived from the signer. The owner is used for authorization only and is not bound into the signed statement.
- **D4 — Billing is out of scope**, with an explicit extension point (§6.9). Today a non-driver SI INSERT is charged 1 query unit to the payer by the `usage` plugin before admission (also when rejected), and inline `VALUES` costs 2 (the evaluation helper query is a second Query packet) (`pkg/plugins/usage/usage.go`, `ReportUsage(ctx, payer, signer, 1)`).
- **D5 — DROP by any database writer.** DROP → retire → purge is allowed for anyone with write permission; this is the contract rule (`deleteTable` requires `isDatabaseWriter`). Same-name re-CREATE must work after purge.
- **D6 — Users read `unsafe_latest` by default.** The server default stays `storage_integrity.read.default_mode: unsafe_latest` (devnet2 today); `SQL_x_read_mode='safe'` remains available per query.
- **D7 — Shared keys through `client_seq` lanes.** Several agents may share one key. Each agent instance owns a random lane id persisted in its state directory; statement identity becomes signer + lane + `client_seq`; the arbiter accumulator (dedup, gap ranges, gap budget K) is kept per (account, lane). Legacy lane-less ids continue as an implicit default lane.
- **D8 — ALTER / mutations and rate limits are out of scope** (next phase).

### 4.2 Technical decisions (decided)

- **D9 — Lane id is 8 random bytes, 16 lowercase hex, carried as a fourth segment of the flat id.** Flat form: legacy `<account>:<seq>:<nonce>`; laned `<account>:<lane>:<seq>:<nonce>`, with `lane` matching `^[0-9a-f]{16}$` exactly. Parsing is by segment count, so the forms are disjoint (a legacy nonce cannot contain `:`). Every pre-lane parser refuses the laned form, so an un-upgraded component fails closed. Size: collisions matter only between lanes of one account; with the D13 cap of 256 lanes the birthday probability is below 10⁻¹³, and the id stays near 113 characters, far below ClickHouse's 64 KiB query-id limit (§3.1, U1). Rejected: lane inside the nonce (old parsers would accept it and the old arbiter would dedup lanes against each other, failing into `DUPLICATE_CLIENT_SEQ` storms); lane inside the account segment (breaks `client_account == recovered signer`).
- **D10 — The JWS binds the lane through `statement_id`; no new purpose or payload field.** `JWSStatementPayloadV2.statement_id` is already the flat string and both the ingress and the FSM recompute it from structured fields, so a laned flat id is signed and verified with the unchanged `auth.StatementPurposeV2` and payload struct. New test vectors go into a separate pinned file (§7) so `auth.SharedStatementVectorsSHA256` and the arbiter's verbatim copy of the existing vectors do not move.
- **D11 — Row ids change only for laned statements; no row-id profile bump.** `RowID` frames the flat statement id as opaque bytes and every component renders it through arbiter-core `StatementID.Flat()`, which gains the lane. Legacy statements render byte-identically, so every historical `_hg_row_id`, partition root and state root is unchanged. `housegate-row-id-v1` stays the profile id.
- **D12 — The accumulator subject is `account` or `account:lane`; the `sentio-spent-ids-v1` byte profile is unchanged.** The FSM derives `subject = account` for legacy and `account + ":" + lane` for laned coordinates (a legacy subject is `0x`+hex and never contains `:`). Leaf preimage, key hash, node hash, K = 64 and proof format are unchanged, so `spent_ids_root` for legacy-only history is unchanged; new golden vectors cover laned subjects.
- **D13 — Activation through a consensus parameter, with a per-account lane cap of 256 (R1), visible to data-plane nodes through the table registry, and gated outside replicated state.** `Params.ClientLanes *ClientLaneParams{max_lanes_per_account}` is absent (omitted from the canonical digest) until an authority-signed `UpdateConsensusParams` sets it; afterwards every update must carry it, `max_lanes_per_account` may only rise, and it can never be removed. Setting it requires `TableRegistry != nil`, and every update that sets or raises it bumps the table-registry version so the existing follower delivers it to sentio-node (§5.4, U12). Before activation a laned statement is `MALFORMED` ("client lanes are not enabled"). After activation the FSM counts distinct lanes per account and refuses a new lane above the cap with `ADMISSION_CODE_LANE_BUDGET_EXCEEDED = 9`. Node capability is advertised in `ProtocolInfo.features` and `NodeRegistration.features` but **never enters a Raft command or replicated state**; activation is gated operationally by `arbiter-admin` on every voter's `GetProtocolInfo` and on the leader's non-replicated feature book for verifiers and SNodes, and after activation the leader's gateway refuses a lane-unaware registration (§5.6). Rationale for the cap: lanes are free to mint but each one leaves a permanent leaf (≈75 bytes plus at most 1 KiB of ranges, plus SMT path nodes); new signer keys are not free once writes require on-chain write permission (D2). The legacy default lane does not count. Rationale for keeping features out of replicated state: the strict Raft command decoder (§3.2) makes any new field inside a replicated command a divergence source while an old voter exists, and a registration applied by an old voter would never carry the field, so an FSM check over stored registrations could not be deterministic across an upgrade.
- **D14 — Lanes are never closed or expired.** The accumulator is a permanent commitment; a closed lane would still have to be remembered to refuse its seqs, so closing saves nothing; expiry needs a clock the FSM must not read, or a block-height rule that would fail an idle user's next INSERT. State is bounded by D13, and lane reuse (D15) keeps the number of lanes per user close to the number of concurrently running agents.
- **D15 — Lane pool with exclusive file locks, Linux and macOS only.** An agent's lanes live under `<si_dir>/lanes/`; at the first SI write the agent takes `flock(LOCK_EX|LOCK_NB)` on the first unlocked, not-abandoned lane and keeps it for the process lifetime; if none is free it mints a new lane. Two processes never share a lane, and a restarted agent reuses its lane. The legacy single-counter file gets the same lock, which closes G5's "no lock" defect for the driver sidecar too. The lock lives behind `//go:build linux || darwin` (the release targets; `syscall.Flock` is missing on some `unix` GOOS such as aix and solaris) with a stub for other platforms that refuses to open a lane store, following the `pkg/secretsload/anonfile_*.go` precedent (U9, §4.5).
- **D16 — Burn fewer seqs and recycle the ones provably unspent; no arbiter release or fill mechanism.** (a) Reserve the seq in `OnQueryInputCompleteStrict` instead of `OnQuery`, which removes burns from client abort, payload-limit refusal, local inline-evaluation failure and cancellation; Relay needs no query-id retagging because `forwardSignedInsert` begins the active query after that hook (§3.1). (b) The server marks every refusal that provably leaves the coordinate unspent with ` [client_seq unspent]`, rendered at one place (`exceptionForPluginError`) from one typed flag and keyed, for arbiter outcomes, on a `SequencedAck` code other than `DUPLICATE_CLIENT_SEQ` — never on `OutcomeTerminalReject` alone (§6.6, U10). The agent returns such seqs to a durable free list and reuses the smallest first; ascending reuse is always a sequential append or a start-edge fill, which never adds a gap range. (c) Seqs with an unknown outcome (transport failure after submission, crash, gRPC-error terminal rejects without a code, sentio-node "Rejected" status, which means sequenced and therefore spent) still burn; they are rare and absorbed by K = 64. (d) A lane that reaches `GAP_BUDGET_EXCEEDED` is abandoned and the agent rotates to a new lane. A permanent wedge is impossible without changing the consensus rule, so G5's "drop the oldest range when the budget is full" arbiter change is not needed.
- **D17 — Permission-based ingress authorization through a host-implemented writer predicate.** housegate adds `registry.WriterAccess` (`IsDatabaseWriter(database, account string) (bool, error)`), implemented by the host over raw chain state with the exact contract semantics (D2); the ingress refuses to start without it. The ingress resolves the owner itself (it does not trust `qctx.Owner`), so it depends neither on `auth.enabled` nor on plugin order. `HasPermission` needs no change: it already expands the hierarchy (§3.3).
- **D18 — The agent discovers the network lazily, per target database.** No SI discovery at startup: at the first INSERT into a database the agent asks the storage RPC of the indexer that hosts that database (`DatabaseInfo.IndexerId → IndexerInfo` storage RPC) for the table status, and on Active asks the same node for SI info (network id, lane support, limits). The agent never signs from a node that does not host the database, which removes G4's "pointed at the wrong node, signs nothing" failure.
- **D19 — SI INSERTs reach the hosting indexer through a neutral agent-side upstream switch (R5); the SI host refuses peer-trusted access to governed ordinary physical tables.** The agent switches its session to the hosting indexer in `sistatement.OnQuery`, before any seq is reserved, through a new `Session.SwitchUpstream` that replays the stored hello with the session database set by fixed rules and refuses a lower-revision upstream; a session whose database or server-side state cannot be carried over is refused locally instead of switched (§6.4). On the SI host, `sipeerguard` refuses any peer-trusted, non-forwarded statement whose identifiers resolve to the ordinary physical table of a non-Ordinary table, in every quoting ClickHouse uses for the measured secondary-query shape (§6.3, U5).
- **D20 — The agent terminates client compression on the SI lane, in a later release (L1).** The agent decompresses client Data, signs and forwards uncompressed, and answers the sample block compressed when the client negotiated compression. Because `clickhouse-client` does not compress towards `localhost` or a local address (§3.6, U8) and the agent listens on `127.0.0.1:9000` by default, this matters mainly for remote agents and drivers; it ships after Phase B as step L1 and is not required for the devnet2 plan.

### 4.3 Resolved in review round 1 (2026-10-08)

The product owner answered every open question of the first draft; R2 is the owner's own answer, the others accept the draft's recommendation.

- **R1 — Lane cap.** A consensus-level per-account lane cap is wanted; the initial value is 256 (D13). It can only be raised.
- **R2 — Default network devnet2; all indexer endpoints public.** With only `-agent-key`, the agent defaults to the `devnet2` preset, whose bootstrap is the public storage RPC `http://64.38.144.158:32003` (indexer-a). Discovery (D18) and the upstream switch (D19) dial `IndexerInfo.indexerUrl` with the advertised ports directly (§3.4). A future mainnet is a second preset.
- **R3 — Ordinary write path aligned with the contract (amended by verification U4).** The ordinary write check uses the contract predicate (no address(0) Write wildcard; the indexer signer counts as a writer) under `auth.writer_predicate`. Because devnet2 has no address(0) grant at all (§3.3), the default is `contract` from the first release, with `bitmap` as an escape hatch; deploying to any other network is preceded by the same measurement (§6.2, §8.2).
- **R4 — Contract NatSpec.** The code is authoritative: Admin alone is not a writer. Fix the `isDatabaseWriter` NatSpec in compute-network-contracts (comment only; no bytecode or behaviour change) (step C1).
- **R5 — Auto-rebind.** The agent switches the session to the hosting indexer for SI INSERTs (D19, §6.4); `--database` stays the documented remedy for reads.
- **R6 — Error codes.** Denylisted signer/owner, invalid operator relation and not-a-writer are refused with 497 (`ACCESS_DENIED`) and close the session on the server; the agent's writer pre-check keeps the common case local and session-preserving (§6.2, §6.4).
- **R7 — Denylist scope.** The denylist applies to the SI ingress lane only; ordinary queries, CREATE and DROP are not affected by it (D1). CREATE/DROP remain governed by write permission (D2, D5).
- **R8 — Driver sidecar.** The driver sidecar stays on legacy (lane-less) ids (`-si-lanes off`); migrating it to a lane after activation is revisited later.
- **R9 — SDK-supplied ids.** With lanes enabled, an SDK-supplied statement id must carry the agent's current lane; otherwise the agent refuses it (§6.5).
- **R10 — Owner audit.** The housegate info log of signer/owner/principal per admitted statement is sufficient for now; the owner is persisted together with billing, through the metering event that already carries it (§6.9).
- **R11 — Billing hook events.** Both events are defined now — sequenced (after admission, housegate `OnStatementSequenced`) and safe (after promotion, `OnStatementSafe`) — and neither is wired to billing in this phase (§6.9).

### 5.6 Node features and the activation gate

The strict Raft command decoder (§3.2) fixes the shape of this mechanism:

- **Nothing new enters a replicated command before activation.** No lane-aware component produces a laned statement while `client_lanes_enabled` is false (§6.4, §6.7), and `NodeRegistration.features` is never copied into a `RaftCommand`. A new leader encoding a registration command with `features` set would make every old follower reject the command at decode while new followers apply it — a membership divergence. A test pins that `RegistrationToPB` and the `RegisterNode` command encoder never set field 5.
- **Feature book.** The `RegisterNode` handler (`arbiter:server/membership.go:16-24`) records `req.GetFeatures()` with the node id and the time into an in-memory, non-replicated book on the voter that handled the request, after the proposal is applied; only the leader accepts proposals, so the leader's book sees every registration made during its term, and a voter clears its book whenever it loses leadership, so every entry is the node's latest registration. `GetNodeFeatures` answers under the same leader barrier `GetConsensusParams` uses: one entry per non-evicted verifier and SNode registration in replicated state, with the book's features for that node (empty when the book has none). A leader change empties the book until nodes re-register; the gate below then refuses, which is the safe direction.
- **Voter probe.** `GetProtocolInfo` (`arbiter:server/consensus_admin.go:35-39`) reports `features: ["client_lanes_v1"]` from lane-aware voters. `arbiter-admin` already probes every voter's `GetProtocolInfo` and refuses on a protocol-version mismatch (`arbiter:cmd/arbiter-admin/main.go:212`, `:225-226`); the feature check slots into the same probe.
- **Activation gate (`arbiter-admin consensus update --client-lanes-max-per-account N`).** Submits only when (1) every voter in the Raft configuration answers `GetProtocolInfo` with `client_lanes_v1`; (2) every entry of the leader's `GetNodeFeatures` carries `client_lanes_v1`; (3) the drain preconditions of `UpdateConsensusParams` hold; (4) the table registry is enabled. Any missing or stale entry refuses with the node ids to restart.
- **After activation.** The leader's `RegisterNode` handler refuses, before proposing, a registration with a verifier or SNode role that lacks `client_lanes_v1` (gRPC `FailedPrecondition`, "client lanes are active; this binary does not support them"), reading `Params.ClientLanes` from its applied state. This is a gateway refusal, not a replicated rule, so it cannot diverge; a mistaken downgrade fails loudly at registration. Voter images must never be downgraded past activation (§7).

### 6.2 housegate: ingress authorization and the ordinary write predicate (D1, D2, D17, R3)

- `pkg/registry/access.go`: add

  ```go
  // WriterAccess answers the contract's Databases.isDatabaseWriter exactly:
  // indexer signer of the database's indexer, or the account's own Owner (0x08)
  // or Write (0x02) bit. Admin alone and address(0) grants do not count.
  type WriterAccess interface {
      IsDatabaseWriter(database, account string) (bool, error)
  }
  ```

  Implemented by sentio-node's `FromStatecore` and `RedisNetworkState` (§6.7; the latter is the registry sentio-node injects) and by `pkg/network/inmemory.go` for tests and YAML-backed servers. `RpcNetworkState` does not implement it.
- New `pkg/plugins/storageintegrity/authorize.go`, `type writeAuthorizer struct{ denied map[string]bool; allowed map[string]bool; writers registry.WriterAccess; operators registry.Access }` with `authorize(signer, payerSetting, database string) (principal string, err error)`:
  1. signer in `denied` → refuse;
  2. owner := normalized `SQL_x_payer`; if set and ≠ signer: `operators.IsOperator(owner, signer)` must hold (refuse otherwise), then owner in `denied` → refuse; principal := owner, else signer;
  3. `allowed` non-empty and signer not in it → refuse (today's behaviour; the `EthValidator` allowlist stays as is);
  4. `writers.IsDatabaseWriter(database, principal)` must be true; an error (unknown database) refuses.

  The database is the logical database of `resolveTargetTable`. The authorizer runs in `OnQuery` immediately after `requireStatementIDSigner`, and again in `admissionFromState` before the admission is handed to the consumer, so a revocation that the mirror sees during a long upload still stops the write. It runs for direct and forwarded-from-peer sessions; the ingress already opts out of peer-trusted and origin-forwarding sessions, which carry no SI write by construction.
- Errors: denylisted signer or owner → `ClientError{Code: 497}` "storage_integrity: signer|owner 0x… is not permitted to write storage-integrity tables"; invalid operator relation → 497 "storage_integrity: 0x… is not an operator of 0x…"; not a writer → 497 "storage_integrity: 0x… is not a writer of database <db>". The OnQuery refusals close the session like other early ingress refusals (they are not added to `isSessionPreservingIngressException`, whose contract requires the input to be consumed). All carry the unspent marker (§6.6). The agent pre-checks writer permission (§6.4) so a user normally sees a local, session-preserving error.
- Config (`StorageIntegrityIngressConfig`, `pkg/config/storage_integrity_config.go:130-137`): add `DeniedAddresses []string yaml:"denied_addresses"` (validated as lowercase 0x addresses, deduplicated); drop the non-empty requirement on `allowed_addresses` (lines 296-297). **Ordinary write path (R3).** New `auth.writer_predicate: contract | bitmap`, default `contract`. With `contract`, `PermissionCommitGateObserver.checkAccess` uses `IsDatabaseWriter(db, principal)` for every policy entry whose required bit is `DbAuthWrite`, instead of the bitmap with the address(0) union; Read, Admin and Owner checks are unchanged. With `auth.enabled` and `contract`, a registry that does not implement `WriterAccess` refuses startup with a message naming `auth.writer_predicate: bitmap` as the escape hatch. Effects: a wildcard Write grant stops admitting writes (aligning INSERT with CREATE/DROP, which already revert on chain for such a caller); the indexer signer becomes a writer of its own databases on non-driver sessions. Exempt session kinds, unchanged: driver, maintenance, platform operator, peer-trusted, origin-side forwarding. Processor traffic is unaffected: processor writes are driver sessions, and processor owners hold Admin|Read, which is not Write today either. On devnet2 no address(0) grant exists (§3.3), so the default changes no outcome there; before a release with this default reaches another network, the same `DatabasePermissionChanged` measurement is run against that network's Databases proxy (§8.2), and a network that relies on a wildcard Write grant sets `bitmap` until its grants are migrated.

### 6.3 housegate: `sipeerguard` on the SI host (D19, G9)

- New query plugin `pkg/plugins/sipeerguard`, registered in `buildServer` only when `storage_integrity.enabled` and `rewriter.physical_database` is non-empty (with an empty physical database no ordinary physical SI table can exist; startup logs that the guard is off). It implements `PeerTrustAware.RunOnPeerTrust() == true` and acts only on sessions with `IsPeerTrusted && !IsForwardedFromPeer`; every other session returns immediately.
- Detection is extraction plus lookup, not a precomputed set: on the SI indexer every non-processor table is governed and unrecorded tables default to Pending, so the governed set cannot be enumerated. The plugin takes the current `TableState` snapshot and scans the statement with the `sireserved` lexer (its executable and literal surfaces, comments and heredocs already modelled). A candidate is:
  1. a qualified name `<db> . <tbl>` on the executable surface where `<db>` equals the configured physical database in any quoting (bare, `` `…` ``, `"…"`) and `<tbl>` is a quoted identifier (`` `…` `` or `"…"`, after ClickHouse escape decoding) — the measured form is `` `devnet2`.`devnet101.swap_new106` ``; `devnet2.\`devnet101.swap_new106\`` and `"devnet2"."devnet101.swap_new106"` are the other quoting variants;
  2. a standalone quoted identifier on the executable surface whose decoded text contains `.` (the physical table identifier `<logical>[<delim><extra>…].<table>` always does, and an unqualified reference resolves against the peer session's physical default database);
  3. a string literal that is an argument of a table-function or table-engine carrier from `sireserved`'s carrier family (`remote`, `remoteSecure`, `cluster`, `clusterAllReplicas`, `merge`, …) and whose text contains `.`.

  Each candidate's table text is split into logical database and table with the rewriter's configured construction (delimiter and extras, then the final `.`); a split that fails is ignored. `snapshot.Lookup(db, table)` with any status other than Ordinary refuses with `ClientError{Code: 392}` "storage_integrity: table <db>.<t> is governed by storage integrity and must be read through its host indexer; connect with --database <db> or USE <db>". A quoted identifier whose escapes the lexer cannot decode the way ClickHouse does is refused with the same code, as `sireserved` does on privileged sessions.
- Confirmed: the `remote()` emission by b's deployed rewriter (form 3 on b's side), the secondary-query form 1 reproduced on ClickHouse 26.3.37.3, and that the ordinary physical table is the target. To be confirmed live during implementation, as a devnet2 step with a non-driver account permitted on `devnet101` through indexer-b (§9.4 step 4): the exact text indexer-b's ClickHouse 26.3.12.1 sends for `count()`, `SELECT *`, a JOIN and an `IN` subquery; and that it reaches indexer-a's HouseGate as a peer-trusted, non-forwarded session. The guard matches all three forms regardless of which one appears.
- Follow-up, not in this phase: the origin rewriter could refuse `remote()` to user databases hosted on the SI indexer to give the error earlier; that needs the SI indexer id in the origin's registry.

**Discovery (D18).**

1. At startup the agent loads the bootstrap registry (`RpcNetworkState`) exactly as today and fails startup only if the bootstrap is unreachable (unchanged `require_network_state`).
2. Status routing: `RpcNetworkState.StorageIntegrityTableStatus(db, table)` resolves `Get(db).IndexerId`, then that indexer's storage RPC endpoint, and calls `sentio_getStorageIntegrityTableStatus` there; it falls back to the bootstrap only when the database is unknown. `registry.ProxyAddress` (`pkg/registry/topology.go:16-19`) gains `StorageRPCPort uint16` from `sentio_getIndexerInfos`' `storageNodeRpcPort` (sentio-node already returns it, §3.4). Results are cached per table for 5 s so a burst of INSERTs costs one lookup.
3. On the first Active answer for a database the agent calls `sentio_getStorageIntegrityInfo` (§6.7) on the hosting indexer's endpoint and caches `{network_id, client_lanes_enabled, ingress_max_payload_bytes, max_token_age_seconds, default_read_mode, server_unix_time}` per database, refreshing it after 60 s and immediately on a lane-related refusal, so a running agent picks up lane activation. The agent warns when `|local − server_unix_time| > 5 s`, because the ingress refuses tokens issued in the future (`max_token_age` 1 m, 5 s skew, `pkg/auth/eth_validator.go:376-386`).
4. Failure modes: status lookup fails → the INSERT passes unsigned and the server answers the retryable 733 "client's table state is stale" (H7, unchanged); info lookup fails or returns no `network_id` → without a configured `storage_integrity.agent.network_id`, local refusal "storage_integrity agent: cannot discover network id from the indexer hosting <db>: <cause>" (the cause names the endpoint); with a configured one, a warning, `clickhouse_proxy_agent_si_discovery_failures_total{step}`, and signing for the configured id, the server staying authoritative (§4.5 P7); a configured `network_id` that differs from the discovered one → refuse (no signing for the wrong network).

**Writer pre-check (advisory).** Before the statement is claimed (not on driver sessions), the agent calls `sentio_isDatabaseWriter(database, principal)` (§6.7) on the hosting indexer's storage RPC and refuses locally, session-preserving, when it answers `false`. An RPC error, including a node that predates the method, is "unknown" and the INSERT proceeds; the server's authorizer stays authoritative. `sentio_getDatabaseInfoByAccount` is not usable here: it returns readable databases merged with address(0) grants and cannot tell a Read-only grantee from a writer (§4.5 P2).

**Upstream switch (D19, G8).** In `sistatement.OnQuery`, after the target resolves to Active and before the statement is claimed, when the database's hosting indexer differs from the indexer of the session's current upstream:

1. *Eligibility.* No switch when `agent.upstream` is pinned (an explicit override wins; the INSERT goes there and the server decides). The session must be switchable: `sistatement` marks a session non-switchable when any statement whose first keyword (after comments and whitespace, by the same lexer `ParseUseDatabaseStrict` uses) is `SET`, `CREATE TEMPORARY`, `BEGIN` or `START TRANSACTION` reaches `OnQuerySuccess`, because session settings, temporary tables and transactions live on the old server and the agent cannot replay them (a proxy-generated replay would be unsigned, §3.4). A non-switchable session refuses locally, session-preserving: "storage_integrity agent: INSERT into <db> must run on indexer <id>, but this session holds server-side state; reconnect with --database <db>".
2. *Session database.* Let `cur` be the agent's effective session database (the committed `USE` target in `sistatement.useDB`, else the hello database) and `D` the target's logical database. The replayed hello's `Database` is `cur` when `cur` is empty, unknown to the registry (e.g. `default`, which the target's `forward` plugin keeps local, §4.5 P10) or hosted by the target indexer (so the server-side `forward` plugin on the target does not pivot the session away, and later unqualified queries keep resolving against `cur`). When `cur` is hosted elsewhere the agent refuses locally, session-preserving: "storage_integrity agent: INSERT into <db> must run on indexer <id>, but the session database <cur> lives on indexer <id2>; use a separate connection with --database <db> or USE <db> first". Chosen over replaying the committed `USE` as an agent-signed query because the hello field carries the same state without a second query, a second success boundary or a query id inside OnQuery, and the refusal covers the one case the hello cannot express without changing the user's session database.
3. *Hello.* A clone of `SessionState.UpstreamHello()` (verbatim `Name`, versions, `User`, `Password`) with `ProtocolVersion = SessionState.ClientRevision` (the client leg's negotiated revision, as `forward` does) and `Database` from step 2.
4. *Dial.* The target's housegate address (`IndexerInfo.indexerUrl` host, `clickhouseProxyPort`) through the agent's `dialRaw` (build.go:1500-1511), so the conn is wrapped in `configuredAddressConn` and the inline-values evaluator and post-commit observers follow the new endpoint.
5. *Switch.* New `Session.SwitchUpstream(ctx, newUp *chproto.Codec, hello *chproto.ClientHello) error` in `pkg/chsession/session.go`: `handshakeNewUpstream` (ClientHello → ServerHello → non-chunked upstream addendum; chunking is negotiated per leg, so the client leg is unaffected), then refuse when the new ServerHello revision is lower than `ClientRevision` (Relay re-frames packets between the legs and cannot down-convert), then stores the new upstream hello with `SetUpstreamHello` and calls `swapAndCloseOld`; the hello is committed only after every check passes, so a refused switch leaves both the bound codec and the stored hello unchanged (`handshakeNewUpstream` itself writes no session state). It writes no peer or forward fields and replays no state; it is not `RebindToPeer` or `RebindToLocal`. A failed handshake or revision refusal closes the new conn, keeps the old upstream and refuses the INSERT locally, session-preserving.
6. *Timing.* The switch runs only inside `OnQuery` on the client→upstream goroutine, where no query is active; Relay refreshes `up` after the chain (relay.go:1199) and `forwardSignedInsert` reads `Upstream()` again (relay_synthesized.go:42). `upstreamToClient` resumes on the new codec when its blocked read on the closed old conn fails (relay.go:1759-1766).
7. The switch is sticky for the session, like `forward`'s USE rebind. Reads are not switched by the agent; `sipeerguard` makes a misrouted SI read fail loudly, and the documented remedy is `--database <db>` (which `forward` handles server-side).

**Materializer default.** With `-si-inline-values auto`, `materialize.enabled` defaults on with `engine: native` and `native_library_release` defaulting to the rewriter-go version in `go.mod`, fetched and verified by `pkg/ffifetch` (linux/amd64 and darwin/arm64). Elsewhere inline `VALUES` stays off with the existing actionable server message, and streaming `FORMAT …` with stdin keeps working. A fetch failure disables inline values with a warning instead of failing agent startup; an explicit `materialize.enabled: true` keeps today's fail-fast.

**Compression.** Until L1 (§6.11) the agent keeps refusing a compressed SI INSERT; its message is extended: "…; clickhouse-client compresses by default only for non-local hosts — connect to 127.0.0.1 or pass --compression 0".

**Settings.** Unchanged: any non-owned query setting on an SI INSERT is refused. The agent's message names the offending key and the `~/.clickhouse-client/config.xml` likely source.

### 6.5 housegate: lanes and `client_seq` in the agent (D7, D9, D15, D16)

- `pkg/plugins/sistatement/seq.go` keeps the legacy counter and gains the lock (`seq_lock_unix.go` with `//go:build linux || darwin`, `seq_lock_other.go` stub) and the durable free list (A1); the lane pool is `pkg/plugins/sistatement/lanepool.go` (B4), reusing that lock:
  - Layout: `<si_dir>/lanes/<lane>.json` = `{"version":1,"lane":"<16 hex>","next":N,"free":[…],"abandoned":false}` written tmp + fsync + rename + dir fsync (today's discipline); `<si_dir>/lanes/<lane>.lock` held with `flock(LOCK_EX|LOCK_NB)` for the process lifetime. The legacy `<state_dir>/<signer>.seq` keeps its format and gains the same lock (`<signer>.seq.lock`) and a durable free list `<signer>.seq.free` (`{"version":1,"free":[…]}`) (§4.5 P3).
  - `AcquireLane()`: iterate lane files in sorted order, skip abandoned, try-lock; on success reuse; else mint `lane = hex(rand[8])`, create the file durably, lock it. Log the lane at info on every start.
  - `Reserve() (seq)`: smallest entry of `free` if any (removed durably), else `next` (then `next+1` persisted). `Release(seq)`: insert into `free` durably; `free` is capped at 64 entries (an overflow drops the largest, which only burns it).
  - `Abandon()`: set `abandoned` durably, unlock, and acquire a new lane for later statements.
- Reservation moves to `OnQueryInputCompleteStrict` for both the deferred and the inline lane, immediately before signing; the strict hook writes the final statement id into `qctx.Query.ID`, which `forwardSignedInsert` records and forwards (§3.1). `OnQuery` leaves the client's query id in place; nothing reaches the server before the hook.
- Release on provably-unspent refusals: the agent's `ExceptionPlugin` inspects the upstream Exception for the active statement and calls `Release(seq)` when the message ends with ` [client_seq unspent]` (§6.6). Agent-local failures after `Reserve` and before the Query is handed to the upstream writer (a signing error, a later strict hook refusing, no upstream, a lost active-query race) release directly; Relay marks these with `QueryContext.UpstreamQueryUnsent`. Once `WriteQuery` has begun, any failure (including a failed write, which may have sent part of the Query), any other Exception, a transport error or a timeout leaves the seq burned.
- Rotation: an Exception naming `ADMISSION_CODE_GAP_BUDGET_EXCEEDED` for this lane → `Abandon()`; the failing statement is reported to the client with "retry: the agent moved to a new client_seq lane" (no automatic resubmission). An Exception naming `ADMISSION_CODE_LANE_BUDGET_EXCEEDED` (a new lane refused at the cap; the seq is unspent and released) switches the agent to the legacy lane for the remaining process lifetime and logs an error naming the cap; if another process holds the legacy lock, SI writes from this process are refused with that reason.
- In-flight cap per lane: `storage_integrity.agent.max_inflight_per_lane` (default 16) SI statements between reservation and outcome. Out-of-order arrival at the arbiter transiently opens one range per in-flight seq above `hi+1`; the cap keeps the transient count far below K = 64.
- SDK-supplied ids (`ownSuppliedStatementID`): legacy form only while lanes are off; with lanes on, an SDK id must carry this agent's current lane, otherwise refused ("SDK statement ids must use lane <lane>") (R9).
- Driver sidecar: `-si-lanes off` (chart default for `housegateSidecar`), so its ids, row ids and file layout are unchanged; it gains only the lock and the recycle path (R8).

### 6.6 housegate: unspent marker on server refusals (D16)

- **Rendering.** One typed flag: `chproto.ClientError` gains `SeqUnspent bool`, and `chproto.MarkSeqUnspent(err) error` wraps any other error. `exceptionForPluginError` (relay.go:2170-2180), the single function every reject path uses through `writeExceptionToClient`, appends ` [client_seq unspent]` in both branches when `errors.As` finds the flag.
- **Who sets it.** For a query carrying `SQL_x_statement_token`:
  1. Relay marks every refusal raised by the OnQuery chain, by `OnClientDataStrict`, by the strict data-limit gate, and its own pre-forward refusals. None of those stages can reach the arbiter, because submission happens only in `ConsumeStorageIntegrityAdmission` under `OnQueryInputCompleteStrict`. This covers every ingress OnQuery refusal (`pkg/plugins/storageintegrity/plugin.go:170-370`: classification, non-INSERT kind, compressed payload, inline SETTINGS, unmaterialized nondeterminism, INSERT shape, target resolution, missing snapshot 392, snapshot schema 60/392, statement-id parse, payload-encoding mismatch, query token, authenticate, the authorizer), the payload cap (plugin.go:381-400) and refusals by earlier chain plugins (auth, commitgate permission observer, sitablestate, querysettings, tablerefguard, rewrite).
  2. In `OnQueryInputCompleteStrict` the ingress marks its own errors: `admissionFromState` failures (JWS, signer mismatch, settings hash, statement kind, schema hash, `StatementPayloadV2Mismatch`, the authorizer re-check); every `ConsumeStorageIntegrityAdmission` refusal before `Orchestrate` (`storage_integrity_ingress.go:535-613`: merge-guard health, materializer selection, missing admission schema, `partsPressureTarget`, `AdmissionRequiresPrepare` preflight, parts-pressure reservation 252, `PutPayload`, empty `payload_ref`); and after `Orchestrate` only when `res.Submit.Category == OutcomeTerminalReject` with a non-empty `AdmissionCode` other than `DUPLICATE_CLIENT_SEQ` (including the 392 `SCHEMA_NOT_ALLOWED` path at lines 684-695).
- **Never marked.** Plain `Orchestrate` errors (a prepare, RC or submit may have happened), retryable and unknown outcomes, journal recovery, gRPC-error terminal rejects (`submitOutcomeFromRPCError`, arbiter_proto.go:397-411: `InvalidArgument` / `PermissionDenied` / `Unauthenticated` / `OutOfRange` carry no code), sentio-node's status-path "Rejected" (`sentio-node:storageintegrityadapter/ingress_client.go:30`, sequenced and therefore spent), and `DUPLICATE_CLIENT_SEQ`.
- **Coded terminal rejects name their code.** The generic "did not reach ACK2" error (storage_integrity_ingress.go:696) becomes, for a terminal reject with a code, "storage_integrity: statement <id> rejected by the arbiter: <ADMISSION_CODE_…>", which the agent's rotation rule reads.
- **Matchers.** `isSessionPreservingIngressException` (relay.go:2194-2210), `chproto.IsTableActivatingMessage` and `chproto.IsTableNoLongerAcceptsWritesMessage` strip the suffix before matching.
- **First presentation only.** The marker is sound only on the first presentation of a statement id. The arbiter checks for a duplicate `client_seq` after its schema, JWS and kind checks, so a resubmitted id whose seq was already sequenced can come back with another code (for example `SCHEMA_NOT_ALLOWED`) and be marked unspent. The agent never presents an id twice: it mints a fresh seq per statement, and `ReserveSupplied` refuses a seq at or below the last one, so an SDK retry of a supplied id whose seq was released is refused with `ErrClientSeqReused`. A third-party signer that re-presents ids must ignore the marker. If this is violated, one statement fails with `DUPLICATE_CLIENT_SEQ`; integrity is unaffected.

## 7. Compatibility and migration

- **Legacy ids stay valid forever.** A lane-less id keeps subject = account, unchanged digests, row ids and roots. Replaying the existing devnet2 Raft log with the new arbiter must reproduce every root (§9.3).
- **Mixed versions before activation.** Lane-aware agents never produce laned ids while `client_lanes_enabled` is false, and a lane-aware ingress refuses them. If one reaches the arbiter anyway: an old leader's gateway drops the unknown field in its proto-to-Go conversion, recomputes the three-segment flat id and answers `INVALID_SIGNATURE`; a new leader answers `MALFORMED`; an old follower that receives a command proposed by a new leader fails to decode it (§3.2) and returns `Rejected` without touching state. Every voter leaves state unchanged, so they cannot diverge. Node features are never in a command (§5.6).
- **After activation.** Every voter must run lane-aware code: an old voter would reject at decode every laned command a new voter applies (fork). The verifier's row ids depend on the leader, not on the verifier: a verifier never parses or re-renders a statement id on the INSERT replay path; it receives each statement's flat id as an opaque string that the leader rendered with its own `StatementID.Flat()` (`arbiter:fsm/reads_dispatch.go`, `replay.Statement{StatementID: ss.Env.StatementID.Flat()}`; `arbiter-core:wire/dispatch.go` `StatementFromPB` copies `statement_id` verbatim) and feeds those bytes into `RowID`, so an old verifier would compute the same row ids and roots as a lane-aware one. A false mismatch would come from a lane-unaware *leader* dispatching a three-segment rendering, which gate (1) of §5.6 (every voter lane-aware) excludes. An old SNode is a liveness hazard, not a safety one: its sentio-node adapter refuses a laned id (fail closed), so SI writes on that node stop until it is upgraded. The verifier and SNode half of the gate (§5.6 (2)) and the post-activation registration refusal are kept anyway, as conservative operational hygiene: they keep the data plane on the release line that has been tested end to end with lanes, they make an old SNode's outage impossible rather than diagnosable, and they ensure that a future verifier path converting a structured `pb.StatementID` (where an old binary would silently drop `client_lane`) cannot meet an old binary; the cost is one verifier RollingUpdate and re-registration. The v18 snapshot rule protects followers, as above.
- **No rollback past activation.** `ClientLanes` cannot be removed, and voter images must not be downgraded below the lane-aware release (a fork); verifier and SNode images must not be either, by the operational rule above (the leader refuses their re-registration). The operational escape hatch is client-side: agents switch to `-si-lanes off` and keep writing legacy ids.
- **Ingress authorization (Phase A)** is independent of lanes. Old agents work unchanged against a new ingress. A new agent against an old ingress works as long as its signer is allowlisted.
- **Old images and the new config.** Configuration decoding is lenient (§3.3): an old housegate or sentio-node image ignores `denied_addresses` without a warning, and its validation still requires a non-empty `allowed_addresses`. Until every SI ingress runs the D17 image, `allowedAddresses` stays non-empty (an old image refuses to start otherwise), and the denylist is not enforced on an old image. The chart's `writerAuthorization` guard plus the reviewed-image list `WRITER_AUTHORIZATION_IMAGES` in `charts/storage-integrity/tests/test_render.py` are the protection against rendering an open allowlist into an old image (§6.10).
- **Agent state.** The legacy `<state_dir>/<signer>.seq` is left in place and used when lanes are off; with lanes on, a new lane starts at seq 1 in its own subject, so nothing migrates.
- **Vectors.** New `pkg/auth/testdata/statement_jws_v2_lanes.json` with its own `auth.SharedStatementLaneVectorsSHA256`; the arbiter copies it verbatim like the existing file. The existing vectors and their pin do not change.

### 8.3 Consensus ordering (Phase B)

The order exists because a voter that does not know a new command field rejects every command carrying it (§3.2):

1. **Before any voter is lane-aware**, nothing lane-related enters a Raft command: agents and ingresses do not emit laned ids (`client_lanes_enabled` is false everywhere), `NodeRegistration.features` is request-only and never encoded into a command, and no `ClientLanes` update is submitted. Verifiers and SNodes may already advertise `client_lanes_v1`; only the voter's non-replicated feature book records it.
2. **All voters lane-aware.** `arbiter-admin` verifies that every voter in the Raft configuration reports `client_lanes_v1` in `GetProtocolInfo`. This is the only point at which a command carrying `client_lanes` may be proposed.
3. **All verifiers and SNodes lane-aware.** Every entry of the leader's `GetNodeFeatures` (one per non-evicted registered verifier and SNode) must carry `client_lanes_v1`. After a leader change the book is empty, so restart the listed nodes to re-register them with the new leader. This step is operational hygiene and SNode liveness, not voter-style safety (§7): verifiers take statement ids opaquely from the leader.
4. **Drain.** All promotions and cleanups acknowledged and promoted unsafe parts cleaned (`arbiter:fsm/consensus_updates.go` preconditions); table registry enabled.
5. **Activate.** `arbiter-admin consensus update --client-lanes-max-per-account 256`, carrying the unchanged `table_registry`. The apply bumps the registry version (sentio-node learns lanes through the follower) and from then on snapshots are v18.
6. **After activation.** The leader refuses lane-unaware verifier/SNode registrations; no voter, verifier or SNode image may be downgraded; agents may emit laned ids once their hosting indexer reports `client_lanes_enabled: true`.

## 11. Risks

- **Consensus change.** Lanes touch admission, accumulator keying, snapshot format and replay. Mitigations: additive omitempty fields, legacy byte identity proved by log replay, features kept out of replicated state, operational activation gate on every voter and every registered verifier/SNode, post-activation registration refusal, v18 written only after activation.
- **Strict command decoding.** Any future field added inside a replicated command needs the same "all voters first" ordering; the decoder makes a mistake visible as a fork, not as silent loss. §9.3 pins pre-activation command bytes against the previous release.
- **Open writes.** Anyone who can obtain write permission on a database on the SI indexer can load the signed lane and the shared back-pressure budget; there are no quotas (D8). The cost of entry is on-chain database creation (charged) or a grant from an owner. The denylist is the only immediate lever and needs a restart.
- **Owner not recorded in consensus (D3).** An operator key's writes are attributable to the owner only through housegate logs and, later, the metering events.
- **Ordinary-path predicate change.** Dropping the wildcard from Write could break a network that relies on public Write grants; devnet2 has none, other networks are measured before rollout, and `bitmap` remains available.
- **Seq recycling relies on server messages.** A server bug that marks a spent seq as unspent produces a `DUPLICATE_CLIENT_SEQ` on reuse: the reusing statement fails, data integrity is unaffected, and the agent drops the seq.
- **Transient gap ranges under concurrency** (§6.5) — bounded by the in-flight cap; measured with a burst test on devnet2.
- **Session switch refusals.** Sessions with server-side state or a database on a third indexer are refused rather than switched; the message names the `--database` remedy.
- **Guard coverage.** `sipeerguard` matches the measured and reproduced forms; the live text from indexer-b is confirmed in §9.4 step 4 before the guard is considered closed for G9.
- **Platform reach.** Release assets and the lane lock exist for linux/amd64 and darwin/arm64 only.
- **Clock skew on user machines** against `max_token_age` 1 m / 5 s future skew; mitigated by the discovery warning, not removed.
