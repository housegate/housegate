# Sentio Arbiter P1d — Real L2 Anchor Backend (Chain-Agnostic EVM) Design

**Phase:** P1d. **Base:** arbiter main `03aa035` (P1c complete: verifier + snode roles, reference binaries, docker integration suite with three fraud-rejection classes), arbiter-proto `v0.2.0` (da.proto merged on main, untagged — context only, not consumed this phase), housegate main `9da80d9`. **Parent designs:** [2026-06-30 Sentio Arbiter design](2026-06-30-sentio-arbiter-design.md) §3.5/§5.2/§10.3/§14 Q5, [P1c design](2026-07-06-arbiter-p1c-dataplane-design.md) §6 (anchor seam), [P1b design](2026-07-05-arbiter-p1b-orchestrator-server-design.md) (config/cmd conventions).

P1d replaces the dev-only `anchor.Local` backend with a real L2 anchoring path: a minimal on-chain `AnchorRegistry` contract plus a chain-agnostic EVM client behind the P1c-frozen `anchor.Client` seam. After P1d the promotability gate `QuorumVerified ∧ finality ∧ last_mergeable` is driven by a real chain's confirmation depth instead of `Local`'s constant `(true, true)`.

## 3. `AnchorRegistry` contract

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

/// Minimal L3-block anchor registry (arbiter design §5.2). v1 posts
/// commitment only: (l3BlockHash, stateRoot). The mapping is the §10.3
/// idempotency anchor: re-anchoring the same pair is a no-op; a
/// conflicting root for an anchored hash reverts.
contract AnchorRegistry {
    struct Entry {
        bytes32 stateRoot;
        uint64 l2BlockNumber; // block.number at first anchor; != 0 marks presence
    }

    address public owner;
    mapping(address => bool) public posters;
    mapping(bytes32 => Entry) public anchors;

    event Anchored(bytes32 indexed l3BlockHash, bytes32 stateRoot, uint64 l2BlockNumber);
    event PosterSet(address indexed poster, bool allowed);
    event OwnerTransferred(address indexed previousOwner, address indexed newOwner);

    error NotOwner();
    error NotPoster();
    error StateRootMismatch();

    constructor(address[] memory initialPosters) {
        owner = msg.sender;
        for (uint256 i = 0; i < initialPosters.length; i++) {
            posters[initialPosters[i]] = true;
            emit PosterSet(initialPosters[i], true);
        }
    }

    modifier onlyOwner() { if (msg.sender != owner) revert NotOwner(); _; }
    modifier onlyPoster() { if (!posters[msg.sender]) revert NotPoster(); _; }

    function setPoster(address poster, bool allowed) external onlyOwner {
        posters[poster] = allowed;
        emit PosterSet(poster, allowed);
    }

    function transferOwner(address newOwner) external onlyOwner {
        emit OwnerTransferred(owner, newOwner);
        owner = newOwner;
    }

    function anchor(bytes32 l3BlockHash, bytes32 stateRoot) external onlyPoster {
        Entry storage e = anchors[l3BlockHash];
        if (e.l2BlockNumber != 0) {
            if (e.stateRoot != stateRoot) revert StateRootMismatch();
            return; // idempotent no-op
        }
        anchors[l3BlockHash] = Entry(stateRoot, uint64(block.number));
        emit Anchored(l3BlockHash, stateRoot, uint64(block.number));
    }
}
```

**Four semantic commitments.** (1) *Idempotency is contract semantics*: a duplicate `anchor` of the same pair succeeds as a no-op — failover double-fires, retries, and the losing side of a nonce race are all absorbed; `anchors[hash].l2BlockNumber != 0` is the check-before-anchor query surface. (2) *Conflict reverts, never overwrites*: same hash + different root → `StateRootMismatch` — only an arbiter bug or key compromise can produce it, so it fails loudly and the mapping is never silently rewritten. (3) *Poster allowlist*: without it, a third party could front-run a known-in-advance `l3BlockHash` with a bogus root, poisoning check-before-anchor; the owner (deployer) manages the list, and deployment seeds it with the arbiter's anchor EOA. (4) *Encoding*: arbiter-side `l3_block_hash`/`state_root` are `replay.DigestString` values (`"0x" + 64 hex`), bijective with `bytes32`; the client converts and rejects malformed input before any tx is sent. `block.number` → `uint64` is safe for any realistic chain height, and EVM block 0 is genesis so 0 is a safe absence marker.

**Toolchain stance (deliberately minimal).** No foundry anywhere. `make gen-anchor-contract` runs `solc` + `abigen` locally and commits the outputs to `anchor/evm/bindings/` (Go bindings + deploy bytecode); the generated file header embeds `sha256(contracts/AnchorRegistry.sol)` and CI re-hashes the source and string-compares — drift detection with zero Solidity toolchain in CI. Contract behavior is asserted from Go tests against the simulated backend (§7), not Solidity tests.

**`cmd/arbiter-anchor` ops CLI** (flag-driven, no yaml — a one-shot ops tool): `deploy --rpc-url --chain-id [--poster addr]... ` (prints the contract address; key via `ARBITER_ANCHOR_EVM_PRIVATE_KEY_HEX`), `set-poster --contract --poster --allowed=bool`, `status --contract --l3-block-hash` (prints the entry and the finality verdict under given depth flags). It reuses the same `anchor/evm` client code — operators need one Go binary and no chain toolchain.

## 4. `anchor/evm` client

Package layout: `anchor/evm/` (client, in-flight tracking, `bindings/`). The client depends on a narrow internal chain-reader interface (contract read, header-by-number/tag, send/lookup tx) satisfied by `ethclient` and by the simulated backend in tests; every chain call carries a `rpc_timeout` deadline so the orchestrator loop stays non-blocking. At startup the client asserts `eth_chainId == cfg.chain_id` (fail-fast on a misconfigured RPC) and derives + logs the EOA address.

**`Anchor(ctx, l3BlockHash, stateRoot)`** — called once per block by the orchestrator, safe to re-enter:

1. Decode both DigestStrings to `bytes32`; malformed → error before any tx.
2. **Check-before-anchor:** read `anchors[hash]`. Present → compare the on-chain `stateRoot` with the argument: mismatch → error (bug/compromise-class incident: the orchestrator warn-loops every pass and a human intervenes; the client never "fixes" a conflicting root); match → return the complete ref (L2 block number from the entry; landed tx hash via one single-block `getLogs`, see below). This branch is the failover re-entry path.
3. Not present, and the in-flight table holds a tx for this hash (regardless of age) → return the existing ref unchanged. All re-drive decisions live in `Finality`'s self-heal — a fresh send here against a still-pending same-nonce tx would be rejected as underpriced replacement, so `Anchor` never re-sends.
4. Otherwise send: `PendingNonceAt` + EIP-1559 pricing (`SuggestGasTipCap`; fee cap = 2× latest baseFee + tip), record `{txHash, nonce, tip, feeCap, sentAt}` in the in-flight table, and **return immediately** with `{L3BlockHash, StateRoot, L2TxRef: txHash, L2BlockNumber: 0}` — never wait for a receipt.

**`Finality(ctx, ref) (Status, error)`** — the once-per-pass, point-in-time check with a bounded self-heal side effect:

- **Entry present on chain:** clear any in-flight record for the hash and judge the two booleans per §5. Enrich the ref: `L2BlockNumber` from the entry; `L2TxRef` corrected via `getLogs(Anchored, hash)` filtered to **exactly the entry's block** (`from == to == l2BlockNumber`) — a precise single-block query, no range scan, cached after first success. Return `Status{Final, LastMergeable, Ref: enriched}`.
- **Entry absent:** the anchor tx has not landed. In-flight and younger than `resubmit_after` → `Status{false, false, ref}` (normal pending). In-flight and older → look the tx up: still pending in the mempool → **replace** (same nonce, tip and fee cap bumped by `gas_bump_percent`, floored at current suggestions); unknown (evicted, or the hash was lost to a restart) → fresh send under a new `PendingNonceAt` nonce. No in-flight record at all (the post-restart norm) → fresh send. All three re-drive paths update the in-flight table and return `Status{false, false, ref}`. This is the **documented self-heal side effect**: it touches only the client's own EOA/txs, never the FSM.
- Chain-read or send errors → `(Status{}, err)`; the orchestrator already warn-and-continues, and the retry ticker re-surfaces the block next pass.

**Concurrency & leader-change analysis.** The orchestrator calls the client single-threaded, so one mutex guards the in-flight table. Two leaders racing with the same EOA either reuse a nonce (one tx replaces the other; the survivor anchors, the loser's Finality self-heal finds the entry present and stops) or use consecutive nonces (both land; the second is the contract's idempotent no-op). With distinct EOAs (both allowlisted), the second `anchor` is likewise a no-op. In every interleaving the mapping converges to exactly one entry, and `StateRootMismatch` is unreachable for honest posters because the FSM's `BlockAnchor` fixes `(ChainHash, StateRoot)` before any anchoring starts.

## 5. Finality judgment

Two configurable modes, both computed against the entry's `l2BlockNumber`:

- **`finality_mode: finalized`** (default): `Final = entryBlock <= finalizedHead` where `finalizedHead` is the block number behind the RPC's `finalized` tag — the chain's own consensus-level finality (on an OP-Stack L2 this inherits L1 settlement). `LastMergeable = Final && confirmations >= last_mergeable_confirmations`, where `confirmations = latestHead - entryBlock + 1`.
- **`finality_mode: confirmations`**: for chains/RPCs without a trustworthy `finalized` tag. `Final = confirmations >= finality_confirmations`; `LastMergeable = confirmations >= finality_confirmations + last_mergeable_confirmations`.

`last_mergeable_confirmations` is the *extra* depth margin on top of finality (base-spec §9's "L1-finalized plus `last_mergeable` depth"); the default `0` makes both booleans flip together — exactly the `Local` backend's `(true, true)` shape, so downstream FSM behavior is a superset, never a divergence. Reorg tolerance falls out of decision 3: a reorg that unwinds the entry makes the next `Finality` pass see an absent mapping and re-drive, and the OR-latched FSM flags (`applyRecordAnchorFinality`) mean an already-recorded finality never regresses — acceptable because both modes are calibrated to judge only at depths where reorgs are out of the chain's threat model.

## 6. Seam refinement and orchestrator adaptation

```go
// anchor/client.go
type Status struct {
    Final         bool
    LastMergeable bool
    Ref           arbiter.AnchorRef // possibly enriched vs the input ref
}

type Client interface {
    Anchor(ctx context.Context, l3BlockHash, stateRoot string) (arbiter.AnchorRef, error)
    // Finality is a non-blocking, point-in-time progress check. EVM
    // implementations may internally re-drive a lost/stuck anchor tx
    // (self-heal); implementations never touch FSM state.
    Finality(ctx context.Context, ref arbiter.AnchorRef) (Status, error)
}
```

`Local.Finality` returns `Status{true, true, ref}` — bit-identical behavior. `orchestrator.anchorBlock` adapts in two lines: the no-progress guard **still compares only the two flags** (`ba.Anchored && st.Final == ba.Finality && st.LastMergeable == ba.LastMergeable` → propose nothing; no raft-log traffic for ref enrichment alone), and the finality propose carries `st.Ref` instead of the stale `ref` — the enriched ref rides the flag-change proposal, which always happens at least once (finality false→true), and `applyRecordAnchorFinality`'s deliberate last-wins anchor content stores it. FSM, wire, proto: zero diff.

## 7. Config and validation

```yaml
anchor:
  backend: evm            # existing allowlist grows: local | evm
  evm:
    rpc_url: "https://..."
    chain_id: 8453
    contract_address: "0x..."
    private_key_hex: "..."           # env ARBITER_ANCHOR_EVM_PRIVATE_KEY_HEX overrides
    finality_mode: finalized         # finalized | confirmations
    finality_confirmations: 12       # confirmations mode only; >= 1
    last_mergeable_confirmations: 0  # extra depth on top of finality
    resubmit_after: 90s              # in-flight age before self-heal re-drive; >= 1s
    gas_bump_percent: 25             # replacement pricing bump; >= 10 (node replacement floor)
    rpc_timeout: 10s                 # per-chain-call deadline
```

P1b `config` conventions throughout: yaml + `Duration` + env override, `Validate()` with `errors.Join`. `backend: evm` requires the four connection fields; `finality_mode` is allowlist-validated; `chain_id` must be nonzero; defaults as shown. `cmd/arbiter` `buildDeps` switches on the existing `anchor.backend` allowlist to construct the client.

## 8. Testing

- **Simulated backend (go-ethereum, in-process — runs under plain `go test`, no docker):** contract commitments (idempotent no-op, `StateRootMismatch` revert, poster gating + `setPoster`, event shape); client paths — fresh anchor returns tx-hash ref; check-before-anchor hit returns the complete ref; on-chain root conflict errors; depth progression flips `Final` then `LastMergeable` under both modes; ref enrichment lands the entry block number and the landed tx hash; self-heal — no blocks mined past `resubmit_after` → same-nonce gas-bump replacement; fresh-client restart (empty in-flight, entry absent) → re-drive; entry present → immediate convergence; two clients, same key, racing `Anchor` on one hash → exactly one entry, one event, both converge. The chain-reader seam lets `finalized`-tag cases fall back to a hand fake if the simulated backend's tag support proves incomplete (verified at plan time); `confirmations` mode is covered full-stack regardless.
- **Orchestrator integration:** existing anchor-flow tests adapt to `Status`; one new test swaps `Local` for the EVM client over a simulated backend and drives seal → anchor → finality → `StatusPromotable` through the real loop.
- **anvil E2E (new env-gated docker CI job, `ARBITER_ANVIL_E2E=1`):** anvil container (foundry image, used as infrastructure only — no foundry in the build), `arbiter-anchor deploy`, then client-level anchor + finality against real JSON-RPC. Deliberately excludes ClickHouse — this job proves the anchor surface only and stays light. CI lists it explicitly, same pattern as the P1c CH job.
- **Config-load + startup smoke** for `cmd/arbiter-anchor` and the `backend: evm` branch of `cmd/arbiter` (chain-id assertion failure is a startup error).

## 9. Acceptance tripwires (P1d-specific)

Must hold: the orchestrator loop gains no blocking call (every chain call bounded by `rpc_timeout`; no receipt waits anywhere); `fsm/` and proto have **zero diff** this phase; `anchor.Local` behavior is bit-identical (existing tests green, only the `Finality` signature adapts); the bindings drift check passes (`sha256(AnchorRegistry.sol)` matches the generated header); a repeated `anchorBlock` pass against an already-anchored block leaves exactly one contract entry and exactly one `Anchored` event; no `AnchorRegistry` write path other than `anchor(bytes32,bytes32)` exists (owner functions touch only ACL state); P1a–P1c CI tripwires stay green.
