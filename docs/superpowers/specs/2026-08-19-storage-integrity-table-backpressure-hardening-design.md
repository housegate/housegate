# Protocol Table and Back-Pressure Hardening

**Date:** 2026-08-19 **Status:** Proposed **Roadmap:** [remediation roadmap](2026-08-19-storage-integrity-remediation-roadmap.md) Spec L. **Remediates:** [Spec C physical table lifecycle](2026-08-18-storage-integrity-physical-table-lifecycle-design.md) (Implemented) — findings from the 2026-08-19 review. **Base:** [2026-06-22 storage integrity design](2026-06-22-storage-integrity-design.md) §12.2, §12.3. **Code base:** arbiter-core `b669ccd` (v0.3.1), arbiter `71657a8` (v0.2.1), housegate `621eaab` (v0.9.3), sentio-node `ba136ea`. **Source of truth:** English version.

## 1. Problem

Spec C's drift detection came out stronger than specified — it requires pinned settings to be *explicit per-table overrides* rather than accepting a matching global, closing a hole the spec's own wording would have left. Partition identity is derived correctly and reuses the existing helpers. Back-pressure genuinely refuses before the payload store, the journal and any source write. The defects are in the inputs to that machinery and in its cost.

**1a — column type strings reach executed DDL unvalidated and unescaped.** `arbiter-core/dataplane/ddl/build.go:41` writes `quoteIdent(c.Name)` followed by a raw `c.Type`, and the result is executed. There is no type allowlist anywhere in `dataplane/ddl`, `snode` or `verifier`; the only type check is `!= "String"` for the partition column. On-chain `setTableSchema` validates only non-emptiness, and the housegate loader's `TableSchemaHash` check proves *authenticity of what was declared*, not that the string is a legal type.

The realistic failure is not injection but a **permanent brick**: a declaration whose type field closes the column list adds an extra column under `ModeCreateAndVerify`; `VerifyProtocolTable` then reports drift and the role fails closed forever, because there is no auto-`ALTER` by design and `CREATE TABLE IF NOT EXISTS` is a silent no-op against the existing table. The node cannot start until an operator manually drops it. The same file already rejects a declared `_hg_row_id` precisely because declarations can be hostile; the type field was left out.

**1b — Spec C D1 ("mode is derived from the schema source") is not enforced, and the zero value is fail-open.** `ProtocolTables ddl.Mode` is a plain config field in both `snode/config.go` and `verifier/config.go`, and neither `validate()` touches it; `schema_source` does not appear in arbiter-core at all. The zero value is `ModeOff`, which returns nil immediately and makes `Run` skip the reconcile goroutine, so a host that omits the field gets silently zero lifecycle enforcement. In the arbiter reference binaries the default mapping is correct but an explicit `-ensure-tables=create` unconditionally overrides a `table_ids` config, with nothing cross-validating; the constraint exists only in README prose, and the test named `TestDefaultEnsureMode_FollowsSchemaSource` covers only the default, never the flag. sentio-node is the one host that derives it correctly.

**1c — every admission runs an unbounded `system.parts` scan, synchronously, serialized, with a hard-coded timeout.** `pkg/storageintegrity/parts_pressure.go:339-348` takes `admissionMu` and calls `Refresh`, whose query returns **one row per active part name** across `hg_unsafe` and `hg_safe` with no aggregation and no bound. `RefreshTimeout` defaults to 2s and there is no config key for it. Spec C D5 specified an interval poll plus cheap invalidation; the implementation additionally does this on the INSERT hot path, and the ingress calls `Invalidate()` after every transition so the poller runs a second full scan per admission.

Because §6 pins `hg_safe` merges off and its part count only grows, this has a cliff: at, say, 10 tables × 12 partitions × 2500 parts the query returns ~300k rows per admission. When it crosses 2s, `checkAvailableLocked` returns unavailable and **every SI INSERT fails closed with 252, permanently**, with no operator knob short of injecting a custom guard at the library boundary. `admissionMu` also serializes all admissions across all tables behind that one query.

**1d — reconcile kills the role on any error, and `Run` has no startup ensure.** The loop returns on the first error and propagates it out of `Run`; a flaky `system.tables` read during a ClickHouse restart is treated identically to real drift, with no `errors.Is(ErrProtocolTableDrift)` discrimination. Separately `Run` performs no ensure of its own and the ticker first fires at t+60s, so a host that calls `Run` without `Register` — or re-runs after a transient failure — has a 60s window with no verification while `convergeStartup` is already touching ClickHouse. In the subscription-first branch, cancelling the in-flight reconcile can surface the reconcile's cancellation error instead of the real subscription error.

**1e — `hg_promote` is in the pinned-DDL table but outside the lifecycle.** `EnsureProtocolTables` creates only the database, and the table is created ad hoc by `snode/promote_replace.go` as `CREATE TABLE IF NOT EXISTS … AS hg_safe.<t>`. It is never rendered by `ddl` and never passed to `VerifyProtocolTable`, so D3's third row has no drift detection; a verify-only node never bootstrapped in create mode fails at first promotion with "database doesn't exist" rather than at startup.

**1f — the 252 rejection closes the client connection.** Spec C D5 chose code 252 so existing client retry logic works unchanged, but the strict-hook rejection path in `runDeferredInsert` treats a non-nil error as session-closing. Under sustained back-pressure — the only condition where this fires — every refused INSERT tears down a pooled connection, converting a throttle into connection churn.

**1g — smaller items.** sentio-node's `hg_safe`/`hg_unsafe` name pin is behind `StorageIntegrity.Enabled` while housegate's is behind `Runtime.Enabled`, so a config with both disabled and `backpressure.enabled: true` passes both validators with a wrong database name; `StorageIntegrityPromoteDatabase` is pinned by neither; `Backpressure.HardPartsPerPartition` is fed into the SNode mirror regardless of `Backpressure.Enabled`, so disabling ingress back-pressure with a zero value silently reverts the source-side mirror to the 2950 default. A single stuck cleanup proof fences SI ingress for every table globally. The verifier does not enforce the partition freeze at config time while the SNode does, so a freeze-violating declaration bricks the SNode but leaves the verifier silently without protocol tables for that table — the exact failure Spec C §1 set out to eliminate.

## 2. Goals / non-goals

Goals: (1) a hostile or merely wrong declaration cannot produce unparseable DDL or an unrecoverable node; (2) the lifecycle mode cannot be silently off; (3) pressure reads are bounded and operator-tunable, and cannot degrade into permanent refusal; (4) transient ClickHouse errors do not kill roles; (5) `hg_promote` is in the lifecycle; (6) back-pressure throttles without tearing down connections.

Non-goals: §12.4 ledger-gated `hg_safe` merges (still P4); partition-key expressions beyond the P1c freeze; auto-`ALTER` on drift (deliberately absent); per-account fair scheduling.

## 3. Decisions

**D1 — Column types are validated against the SI profile's own supported set.** `payloadexec`'s executor already enumerates the MVP whitelist (`String`, `FixedString(N)`, `Bool`, `Float32/64`, `[U]Int8/16/32/64`). Export that check and call it from `Intents`, so `BuildDDL`, `EnsureProtocolTables` and both roles' `validate()` are covered by one gate. A type outside the set is a rejection naming the table, the column and the offending string; the reject happens **before** any `CREATE`. Rejected: parsing the type with ClickHouse's grammar — it would admit types the replay executor cannot materialize, which is a worse failure (silent divergence) than refusing to create.

**D2 — Mode is derived, not configured, and there is no fail-open zero value.** Add `SchemaSource` to both roles' configs, derive `ddl.Mode` from it inside `validate()`, and make the derived mode the only input to `EnsureProtocolTables`. `ModeOff` remains for tests but is no longer reachable from a production config path; the roles' `validate()` rejects an unset schema source. In the arbiter binaries, `-ensure-tables` becomes a *check* rather than an override: if it disagrees with the schema source, refuse to start with a message naming both. Keep the collision validation ahead of every short-circuit, as it already is.

**D3 — Pressure reads become bounded aggregates scoped to the statement.** Two changes: (a) the hot-path check reads only the `(table, partition)` pairs the statement actually touches, via an aggregate `count()` grouped query with those pairs bound as parameters — not a full inventory; (b) the exact-name inventory, which the reservation/cleanup-proof protocol genuinely needs, stays on the interval poller and is scoped per table. `refresh_timeout` and `snapshot_ttl` become `storage_integrity.runtime.backpressure` config keys with the current values as defaults, validated as positive. Drop the per-admission `Invalidate()`-triggered second scan; invalidation marks the snapshot stale for the poller rather than forcing an immediate full read. `admissionMu` is scoped per table so one table's read cannot serialize another's admissions. The fail-closed posture on genuinely unavailable inventory is unchanged — the fix is that "unavailable" stops being reachable by growth alone.

**D4 — Reconcile distinguishes drift from transient failure.** `errors.Is(err, ErrProtocolTableDrift)` (and the collision/type errors from D1) kill the role; anything else is retried with bounded backoff and logged, and only escalates after a configurable number of consecutive failures. `Run` performs an ensure before entering its loop, so there is no unverified startup window, and the subscription-cancellation path returns the original error rather than the cancellation artifact.

**D5 — `hg_promote` enters the lifecycle.** Render it from `ddl` alongside the other two, create it in `EnsureProtocolTables` under create mode, and verify it in `VerifyProtocolTable`. `promote_replace.go` stops creating it ad hoc and instead fails with a clear error if it is absent, which is now a startup-detectable condition rather than a first-promotion surprise.

**D6 — Back-pressure rejects without closing the session.** The 252 rejection returns to the client as an Exception on a session that stays usable, matching D5's stated rationale. Concretely: the strict-hook contract gains a rejection class that writes the Exception, aborts the query, and resumes the packet loop rather than closing. Rejected: leaving it as-is — the throttle fires precisely when connection churn is most expensive.

**D7 — The smaller items.** Pin `hg_safe`/`hg_unsafe`/`hg_promote` names in one validator that runs whenever any SI feature is enabled (ingress, runtime, backpressure or read), in both housegate and sentio-node; feed the SNode mirror limit only when back-pressure is enabled, and pass an explicit disable otherwise; scope a stuck cleanup proof's fence to the affected table; make the verifier enforce the partition freeze at config time exactly as the SNode does, so a freeze-violating declaration fails both roles identically instead of half-silently.

## 4. Testing / acceptance

- A declaration with a type outside the whitelist is rejected by `BuildDDL`, by `EnsureProtocolTables` and by both roles' `validate()`, before any `CREATE`; a docker test proves no table is created.
- A config without a schema source fails role construction; `-ensure-tables=create` with a `table_ids` config fails the binary with a message naming both.
- Pressure: a docker test with a table holding several thousand parts shows the hot-path query returning a bounded row count and completing well inside the timeout; a unit test proves the touched-pairs query is parameterized by exactly the statement's partitions; `refresh_timeout`/`snapshot_ttl` are honoured from config.
- A transient (non-drift) ClickHouse error during reconcile is retried and the role survives; a real drift kills it. Both asserted distinctly.
- `hg_promote` drift is detected at startup; `promote_replace` errors clearly when it is absent.
- Back-pressure refusal: the client receives Exception 252 **and the connection remains usable for a subsequent query** (this is the regression test for D6).
- sentio-node's SI smoke (now running in CI per Spec J) covers the type-validation reject and the survivable-throttle behaviour.

## 5. Delivery

1. arbiter-core: D1 type validation in `Intents`, D2 schema-source-derived mode, D5 `hg_promote` in the lifecycle, D4 reconcile resilience, D7 verifier freeze parity → tag.
2. arbiter: binaries consume the derived mode and turn `-ensure-tables` into a check → tag.
3. housegate: D3 bounded/scoped pressure reads + config keys, D6 non-closing rejection, D7 name pinning → tag.
