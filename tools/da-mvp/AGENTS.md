# DA MVP GUIDE

## OVERVIEW
`tools/da-mvp` is a distinct experimental tool subtree for data-availability publication/rebuild flows. It shares repo Bazel conventions but is not part of the main `housegate` binary.

## STRUCTURE
```
tools/da-mvp/
|-- cmd/          # da-publisher, da-rebuilder, loadgen, pfb-demo
|-- pkg/          # anchor, celestia, checkpoint, chunk, schema, verify, CH import/export
|-- contracts/    # Foundry project and generated Go binding
`-- scripts/      # experiment and deployment scripts
```

## WHERE TO LOOK
| Task | Location | Notes |
|------|----------|-------|
| Publisher/rebuilder binaries | `cmd/da-publisher/`, `cmd/da-rebuilder/` | Separate binaries, not `housegate` subcommands. |
| Contract source | `contracts/src/DAAnchor.sol` | Foundry owns Solidity build/test. |
| Go contract binding | `contracts/binding/` | Regenerated by script; do not hand-edit generated binding logic. |
| Celestia path | `pkg/celestia/`, `cmd/pfb-demo/` | External network/service assumptions. |
| Experiment scripts | `scripts/` | Operational runs, metrics collection, binding regeneration. |

## CONVENTIONS
- Keep MVP tool code isolated under `tools/da-mvp` until there is an explicit promotion into production packages.
- Build Go code with Bazel when checking repo integration.
- Use Foundry commands inside `contracts/` for Solidity tests and ABI generation.
- Scripts are operational artifacts; preserve env var names and expected output formats.
- Treat generated bindings as outputs of contract ABI changes.

## ANTI-PATTERNS
- Do not wire DA MVP commands into `cmd/housegate` without a design decision.
- Do not make production packages depend on experimental DA MVP code casually.
- Do not edit vendored `contracts/lib/forge-std` content.
- Do not mix Foundry build outputs into Bazel source files unless the generation path is documented.

## COMMANDS
```bash
bazel test //tools/da-mvp/...
bazel build //tools/da-mvp/cmd/da-publisher:da-publisher //tools/da-mvp/cmd/da-rebuilder:da-rebuilder
cd tools/da-mvp/contracts && forge test
tools/da-mvp/scripts/regen-bindings.sh
```

## NOTES
- `tools/da-mvp/contracts/lib/forge-std` is third-party Solidity test support.
- Some integration-style anchor/Celestia paths require local services or network configuration; check test skips before treating absence as a regression.
